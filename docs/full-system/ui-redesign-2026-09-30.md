# บันทึกปรับหน้าจอ PairEval สำหรับอาจารย์และนักศึกษา (30 กันยายน 2026)

## สิ่งที่ปรับ

- ปรับหน้า `/full-system` ให้เป็นหน้าเริ่มงานเดียวกันของทั้งสองบทบาท โดยแสดงห้องเรียนเป็นการ์ดพร้อมบทบาทและทางเข้าที่ตรงกับสิทธิ์; เพิ่มแบบฟอร์มสร้างห้องเรียนสำหรับบัญชีที่มีสิทธิ์ โดยใช้ API เดิมและตัวอย่าง CSV
- จัดหน้าจัดการของอาจารย์เป็นลำดับงาน: เลือก/สร้างงาน, ตั้งค่า, ตรวจแผนจับคู่และเผยแพร่; ย้ายการแก้รายชื่อและเครื่องมือถอนข้อมูลสังเคราะห์ไว้ในส่วนพับได้
- ปรับหน้างานของนักศึกษาให้เห็นสถานะและกำหนดส่ง Group/Individual แยกกัน; เพิ่มคำอธิบายคะแนนแบบพับเก็บ
- ปรับหน้าประเมินให้เห็นความคืบหน้า กำหนดส่ง การเปรียบเทียบผลงาน A/B และความหมายของระดับ 1–6 ชัดขึ้น; แสดงสถานะบันทึกอัตโนมัติและปุ่มส่งที่ใช้งานสะดวกบนมือถือ
- ปรับรายงานอาจารย์กับหน้าคะแนนนักศึกษาให้ใช้หัวข้อ ภาษาไทย และสถานะข้อมูลที่อ่านเข้าใจง่ายขึ้น; จัดแท็บรายงานและการ์ดคะแนนให้เหมาะกับจอเล็ก
- เพิ่มทางกลับจากหน้า Group/Individual ไปยังรายการงานของห้องเรียนเดิม พร้อมปรับระยะห่าง สี สถานะปุ่ม และ focus สำหรับคีย์บอร์ด/จอแคบ

## ผลตรวจจริง

- `npm run typecheck` ผ่าน
- `npm run lint` ผ่าน
- `npm run build` ผ่าน
- GUI smoke ด้วยข้อมูลสังเคราะห์บน build ในเครื่อง ผ่าน: อาจารย์เปิดแดชบอร์ดและเข้าจัดการห้อง, สร้าง/เผยแพร่งาน; นักศึกษาเปิดแดชบอร์ดและรายการงาน จากนั้นทำ Group และ Individual ผ่านปุ่มบนหน้าเว็บ รวมบันทึกฉบับร่าง โหลดกลับ ส่ง และส่งแก้ไข; ตรวจรายงาน Interim, My Score, การปฏิเสธหลัง deadline และการไม่เปิดเผยตัวผู้ประเมิน
- ชุด smoke จบด้วย exit code 0 และรัน cleanup ของ fixture สำเร็จ
- ทดสอบฟอร์มสร้างห้องเรียนผ่าน GUI ด้วยบัญชีอาจารย์และ CSV สังเคราะห์บน development: ส่งฟอร์มสำเร็จ, หน้าแสดงข้อความสร้างห้อง, ฐานข้อมูลยืนยันห้องเรียน 1 ห้อง นักศึกษา 2 คน และ 1 กลุ่ม; cleanup ลบข้อมูลทดสอบในฐาน operational สำเร็จ
- การสร้างห้องเรียนบันทึก audit outcome ที่มีรหัสผู้ใช้/ห้องสังเคราะห์ตามกลไก append-only; ไม่ลบประวัติ audit ที่ส่งสำเร็จ
- ตรวจหน้าเข้าสู่ระบบที่ 545×486 ใน browser local; เนื้อหาหลักและปุ่มเข้าสู่ระบบแสดงครบ

## ขอบเขตและงานต่อ

- การตรวจนี้ใช้บัญชีและข้อมูลสังเคราะห์บน development เท่านั้น ไม่ได้ deploy ไป staging และไม่ได้ใช้บัญชีจริง
- เมนูของบทบาท TA ยังไม่มีหน้าจัดการเฉพาะในต้นแบบ; หน้า dashboard แสดงสถานะนี้ตามจริง
- ขั้นถัดไป: ให้ตัวแทนอาจารย์และนักศึกษาทบทวนหน้าจอ และตัดสินใจแยก UI ของ TA หากยังอยู่ในขอบเขต
