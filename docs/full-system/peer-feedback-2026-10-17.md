# แก้ปัญหาจากเพื่อนทดลอง — 17 ตุลาคม 2026

## รายงานและการทำซ้ำ

เพื่อนส่งรายงาน 2 ข้อจากรุ่น `2028c0b` ทำซ้ำได้บน production build/local ด้วยข้อมูลสังเคราะห์ในสำเนาทดสอบแยก ไม่แก้ working tree เก่า, Lab, submodule หรือฐาน staging

### 1. กำหนดส่งรายบุคคลเด้งกลับหลังบันทึก

ภาพรายงานเป็นงานที่คะแนนรายบุคคลเท่ากับ **0** ระบบจึงไม่เปิดใช้ด้านนี้ API ไม่อนุญาตแก้ deadline ของด้านที่ไม่เปิดใช้ แต่ UI รุ่นเดิมยังให้กรอกวันที่และแสดงข้อความว่าบันทึกแล้ว โดยไม่ได้ส่งค่าด้านนี้

แก้ให้ช่อง deadline ของด้านคะแนน 0 เป็นช่องว่างที่แก้ไม่ได้ พร้อมคำอธิบายว่าไม่เปิดใช้ด้านนี้ ปุ่มบันทึกใช้ได้เมื่อเปลี่ยนกำหนดส่งของด้านที่เปิดใช้งานจริง และ PATCH ส่งเฉพาะค่าที่เปลี่ยน เพื่อไม่ส่ง deadline อีกด้านที่ผ่านไปแล้วกลับไปตรวจเป็นวันใหม่

ผล GUI/API:

- งาน Group อย่างเดียว: ช่อง Individual disabled และว่าง มีคำอธิบาย ปุ่มบันทึก disabled จนกว่าจะเปลี่ยน Group
- งานสองด้านที่เปิดใช้: ขยาย Individual หลัง Group ผ่านกำหนดตามเวลาจริงแล้วได้ ส่งเฉพาะ `individualDeadline` และค่า Group เดิมไม่เปลี่ยน
- เปิดหน้าใหม่แล้ววันที่ที่บันทึกยังตรง โดยแสดง timezone Asia/Bangkok

### 2. ปิดคำอุทธรณ์ได้ก่อนยืนยัน Final ฉบับใหม่

รุ่นเดิมยอมให้ `PATCH appeals` ตอบ 200 และปิดคำขอขณะที่งานเป็น `CLOSED` หลัง Reopen จริง

แก้การตอบและปิดคำขอทั้ง `RESOLVED`/`REJECTED` ให้ต้องเป็นงาน `FINALIZED` และ snapshot ล่าสุดของ generation ปัจจุบันเป็น `FINAL` โดยตรวจภายใต้ assignment lock ใน transaction เดิม หากกำลังทบทวนจะตอบ **409** และคำขอยัง OPEN

UI แสดงคำอธิบายและปิดปุ่มตอบกลับ/ปฏิเสธจนกว่าจะยืนยัน Final; audit ของการปิดคำขอระบุ Final snapshot ที่ใช้ตอบด้วย ไม่มี migration ใหม่ และยังเก็บ reference ของ Final ที่นักศึกษายื่นอุทธรณ์เดิมไว้

หากอาจารย์อธิบายผลโดยไม่เปิดทบทวน/ไม่เปลี่ยนคะแนน สามารถตอบคำขอบน Final ปัจจุบันได้ ไม่บังคับสร้าง Final ซ้ำโดยไม่มีเหตุ การแก้นี้ป้องกันปิดคำขอขณะยังทบทวนผลอยู่

## ให้เพื่อนตรวจซ้ำ

หยุดบริการในโฟลเดอร์ที่ใช้อยู่ จากนั้นตรวจ `git status` และอัปเดต main ตาม [คู่มือ](../GETTING_STARTED.md#6-อัปเดตรุ่นภายหลัง) โดยเก็บข้อมูลเดิมไว้:

```powershell
git pull --ff-only origin main
npm ci
npm run build
.\Open-PairEval-Demo.cmd
```

1. งานคะแนนรายบุคคล 0: ช่อง deadline Individual ต้องแก้ไม่ได้และมีคำอธิบาย
2. งานคะแนนรายบุคคลมากกว่า 0: ขยาย deadline แล้วบันทึกและเปิดใหม่ วันที่ต้องคงอยู่
3. งานมีอุทธรณ์: Owner Reopen → ปุ่มปิดคำขอต้อง disabled → ปรับคะแนน → Final ใหม่ → ตอบและปิดคำขอ → นักศึกษาเห็นผลใหม่

หากมี source แก้ค้าง ห้าม reset/clean ทิ้งเพื่อ pull และไม่ใช้ `seed:reset` กับฐาน Full System
