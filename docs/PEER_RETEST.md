# ให้เพื่อนตรวจซ้ำรุ่นล่าสุด — 17 ตุลาคม 2026

รุ่นนี้รวมการแก้ปัญหาและผลตรวจ UI ครบ 98 กรณีแล้ว ใช้ข้อมูลและบัญชีสมมติเดิม ไม่ต้องล้างฐานหรือเริ่มติดตั้งใหม่ ผลจากเครื่องผู้พัฒนาอยู่ใน [รายงาน 98 กรณี](testing/MANUAL_UI_98_RESULTS_2026-10-17.md) ยังต้องตรวจบนเครื่องเพื่อนด้วย

เริ่มจากรายการสั้นด้านล่างประมาณ 20–30 นาที หากต้องการตรวจทั้งระบบ ใช้ [คู่มือ Manual UI 98 กรณี](MANUAL_UI_TEST.md) และคัดลอก [แบบบันทึกผลเปล่า](testing/MANUAL_UI_RESULTS_TEMPLATE.md) เป็นไฟล์ของตนเอง เผื่อเวลารอ deadline ตามคู่มือด้วย

## 1. อัปเดตรุ่นก่อนเริ่ม

เปิด PowerShell ในโฟลเดอร์เดิมที่มี `package.json`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-PairEval-Demo.ps1
git status --short
```

ถ้ามี source ที่แก้เอง ให้เก็บงานและตรวจ diff ก่อน อย่าใช้ reset/clean ทิ้ง ถ้าไม่มีงานค้าง:

```powershell
git pull --ff-only origin main
npm ci
npm run build
git rev-parse --short HEAD
.\Open-PairEval-Demo.cmd
```

เปิด **http://localhost:3103** เลือกบัญชีจำลอง บันทึก commit ที่คำสั่งแสดงในผลส่งกลับ ใช้ main ล่าสุดที่รวมรายงานตรวจ UI 98 กรณี

หากรับเป็น ZIP ให้ใช้ ZIP รุ่นล่าสุดและแตกในพาธภาษาอังกฤษ ไม่คัดลอก `.env.local` หรือ `.verification` ข้ามโฟลเดอร์ ดู [คู่มือติดตั้ง](GETTING_STARTED.md) แทนคำสั่ง Git

## 2. ตรวจเรื่องกำหนดส่ง

เลือก **อาจารย์เจ้าของห้อง → ห้องเรียน → จัดการงาน → เลือกงาน → รายละเอียด กำหนดส่ง และเกณฑ์คะแนน**

| กรณี | สิ่งที่ลอง | ผลที่ควรได้ |
|---|---|---|
| งานคะแนนรายบุคคล 0 | ดูช่องกำหนดส่งรายบุคคล | ช่องว่าง แก้ไม่ได้ มีข้อความว่าไม่เปิดใช้ด้านนี้ |
| ยังไม่ได้เปลี่ยนวันที่ | ดูปุ่มบันทึกกำหนดส่ง | ปุ่มยังใช้ไม่ได้ ไม่มีการบอกว่าบันทึกทั้งที่ไม่เปลี่ยนอะไร |
| งานคะแนนรายบุคคลมากกว่า 0 | เปลี่ยนเฉพาะกำหนดส่งรายบุคคลเป็นเวลาข้างหน้า แล้วบันทึก | บันทึกได้ วันของกลุ่มไม่เปลี่ยน |
| หลังบันทึก | refresh แล้วเปิดงานเดิมอีกครั้ง | วันที่รายบุคคลตรงกับที่บันทึก แสดงตาม timezone ห้องเรียน |

ถ้ากำหนดส่งกลุ่มผ่านไปแล้ว ยังขยายเฉพาะรายบุคคลได้โดยไม่ต้องแก้วันของกลุ่ม ถ้าต้องการเปิดใช้รายบุคคล ให้ตั้งคะแนนมากกว่า 0 และเกณฑ์ของด้านนี้ตั้งแต่ DRAFT; งานที่เผยแพร่แล้วให้คัดลอกเป็นงานใหม่เพื่อเปลี่ยนการตั้งค่า

## 3. ตรวจเรื่องอุทธรณ์และ Final

ใช้ `ตัวอย่างปิดงาน · คะแนนและอุทธรณ์` ที่เตรียมไว้ หากยังไม่มี ให้รัน `npm run demo:prepare-final` ขณะบริการเปิดและรอ deadline 5 นาทีจริง

1. **Owner:** เปิดรายงานและยืนยัน Final หากยังไม่ยืนยัน
2. **นักศึกษาคนที่ 1:** เปิดคะแนน Final แล้วส่งคำขอทบทวนอย่างน้อย 20 ตัวอักษร ถ้ามีคำขอ OPEN อยู่แล้ว ให้ใช้คำขอนั้น
3. **Owner:** จดคะแนนเดิม → กาง **เปิดทบทวนคะแนนที่ยืนยันแล้ว** → ใส่เหตุผลอย่างน้อย 10 ตัวอักษร → กด **เปิดคะแนนให้แก้ไข**
4. เลือกคำอุทธรณ์และกรอกคำตอบอย่างน้อย 10 ตัวอักษร **ปุ่มยืนยัน/ตอบกลับและปฏิเสธต้องยังใช้ไม่ได้** พร้อมข้อความให้อาจารย์ยืนยันคะแนนก่อน
5. กาง **ปรับคะแนนพร้อมเหตุผล** ซึ่งอยู่เหนือส่วนคำขอ → เลือก **รายบุคคล** → นักศึกษาคนที่ 1 → ใส่คะแนนใหม่ที่ต่างจากเดิมและไม่เกินคะแนนเต็ม เช่น 4.25 จากเต็ม 5 → ระบุเหตุผล → **บันทึกการปรับคะแนน**
6. ขณะเป็น Interim ปุ่มปิดคำขอต้องยังใช้ไม่ได้ จากนั้นกด **ยืนยันผลคะแนน** ด้านบนและยืนยันในกล่อง ปุ่มตอบกลับจึงใช้ได้
7. ตอบและปิดคำขอ → สลับเป็นนักศึกษาคนที่ 1 → refresh หน้าคะแนน ต้องเห็นองค์ประกอบคะแนนรายบุคคลใหม่ คะแนน Final ล่าสุด และคำตอบอาจารย์
8. ปิด–เปิดระบบตาม Stop/Open script แล้วเปิดคะแนนอีกครั้ง ข้อมูลต้องยังอยู่

ไม่ใช้คะแนนรวม 16.94 หรือเลขจากรูปเก่าเป็นคำตอบตายตัว ให้เทียบองค์ประกอบ/คะแนนรวมกับรายงาน Final ของ snapshot ปัจจุบัน หากไม่ได้ปรับคะแนนและไม่ได้ Reopen อาจารย์ตอบชี้แจงบน Final เดิมได้ตามปกติ

## 4. ตรวจจุดที่แก้เพิ่มในรอบ 98 กรณี

| สิ่งที่ลอง | ผลที่ควรได้ |
|---|---|
| เข้าหน้าแรกและสลับบทบาท | ห้องและเมนูตรงกับบทบาท; หากโหลด session ไม่สำเร็จ แสดงข้อความให้ลองใหม่ ไม่สรุปว่าออกจากระบบ |
| เปิดด้านประเมินที่งานไม่ได้เปิดใช้ | แสดงเหตุผลและทางกลับ ไม่ค้างกำลังโหลด |
| ดูแผนจับคู่ของห้องที่มี 3 กลุ่ม | เห็นทั้งเหตุผลของแผนและคำเตือนความเชื่อมั่นต่ำ |
| นักศึกษาหรือ TA เปิด URL รายงานที่ไม่มีสิทธิ์ | เห็นข้อความปฏิเสธ ไม่มีปุ่มคำนวณหรือข้อมูลรายงาน |
| ใช้ Tab เข้าตารางรายงาน/แผนจับคู่/คลังห้อง | เห็นกรอบโฟกัส และใช้ลูกศรเลื่อนตารางได้เมื่อจอแคบ |
| ประเมิน → ส่ง → กลับเข้ามาตรวจ/ส่งซ้ำ | ข้อมูลที่ส่งถูกต้อง เวลาประเมินไม่เดินต่อระหว่างยืนยันหรือส่งข้อมูล |

ห้ามแก้หรือส่งคะแนนงานจริงเพื่อทดสอบ ใช้ห้องและบัญชีสมมติเท่านั้น
