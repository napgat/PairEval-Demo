# สคริปต์สาธิต PairEval — เปิดตาม กดตาม อ่านตาม

สำหรับผู้นำเสนอที่ยังไม่คุ้นกับระบบ · ปรับปรุง 19 ตุลาคม 2026 · อ้างอิง Full System ตั้งต้น `4e8498d` พร้อมการแสดงเวลาตามห้องเรียนที่ส่งมอบในรุ่นเดียวกับเอกสารนี้

**ใช้เอกสารนี้เป็นบทพูด ไม่ต้องอ่านชื่อไฟล์ คำสั่ง หรือหมายเหตุทั้งหมดให้อาจารย์ฟัง** ข้อความในกรอบคำพูดคือส่วนที่อ่านออกเสียงได้ เปลี่ยนคำแทนตัวให้ตรงกับตนเองได้

ระบบที่สาธิตเป็นต้นแบบโครงงานนักศึกษา ใช้ข้อมูลจำลองในเครื่อง ไม่ใช่ระบบบันทึกคะแนนจริง

## วิธีอ่านเอกสารนี้

- **เปิด/กด:** ทำตามบนหน้าเว็บ
- **ชี้:** เลื่อนเมาส์ไปที่ข้อความหรือส่วนที่ระบุ แล้วหยุดให้ผู้ชมดู
- **พูด:** อ่านข้อความในกรอบคำพูด
- **เห็นแล้วไปต่อ:** ตรวจสิ่งที่หน้าจอแสดงก่อนเปลี่ยนขั้น
- **ถ้าไม่เหมือน:** ใช้ทางแก้ในช่วงนั้นหรือท้ายเอกสาร ไม่ต้องเดาว่าระบบทำสำเร็จ

**เวลาโดยประมาณหลังเตรียมเครื่อง:** บทพูดนำ 1 ประมาณ 3–4 นาที และบทหลัก 2–12 รวมประมาณ 35–50 นาที; บทเสริม ก–ฉ อีก 20–30 นาที เลือกแบ่งนำเสนอหลายรอบได้ การสาธิตไม่ใช่การไล่ทดสอบครบ 100 กรณี

## 0. เตรียมก่อนเริ่ม — ทำเงียบ ๆ ยังไม่ต้องแชร์หน้าจอ

### 0.1 เปิดโปรแกรม

1. ใช้โฟลเดอร์โปรเจกต์ที่ติดตั้งไว้แล้วและมีไฟล์ `package.json` เปิดชุดเดียวในเครื่อง
2. ดับเบิลคลิก **Open-PairEval-Demo.cmd** รอหน้าตัวเลือกบทบาทที่ [http://localhost:3103](http://localhost:3103)
3. ถ้าติดตั้งครั้งแรก ให้ทำ [คู่มือติดตั้ง](GETTING_STARTED.md) ให้จบก่อนวันนำเสนอ ไม่เริ่มติดตั้งแพ็กเกจสดต่อหน้าผู้ชม
4. หน้าแอปอยู่ที่ [http://localhost:3101/full-system](http://localhost:3101/full-system) แต่เวลาเข้าหรือสลับบัญชีให้กลับ **3103**
5. ใช้ browser เดิมตลอดการสาธิต แต่ละบทบาทเปิดจาก 3103 ได้ การสลับบทบาทเปลี่ยนบัญชีของ **ทุกแท็บใน browser profile เดียวกัน** กลับแท็บเก่าต้อง refresh ก่อนใช้

**สำหรับเครื่องที่ผู้พัฒนาเตรียมไว้ในแชตนี้:** ชุดสาธิตอยู่ที่ `E:\PairEval-Professor-Review-20261016` ให้เปิดตัว .cmd จากชุดนั้น หากเปลี่ยนเครื่องให้ใช้โฟลเดอร์ที่ติดตั้งของเครื่องใหม่ ไม่คัดลอกฐานหรือ `.env` ข้ามเครื่อง

### 0.2 เตรียมงาน Final ไว้ก่อน เพื่อไม่ต้องรอตอนสาธิต

1. เมื่อเปิดบริการแล้ว เปิดโฟลเดอร์เดียวกันใน File Explorer
2. คลิกแถบที่อยู่ด้านบน พิมพ์ `powershell` แล้ว Enter จะได้หน้าคำสั่งที่อยู่ในโฟลเดอร์นั้น
3. วางคำสั่งต่อไปนี้แล้ว Enter:

```powershell
npm run demo:prepare-final
```

4. รอจนคำสั่งทำเสร็จ แล้วเข้า Owner → ห้อง **PairEval · สาธิต PRD v2.0** → เลือกงาน **ตัวอย่างปิดงาน · คะแนนและอุทธรณ์**
5. ดูกำหนดส่งที่หน้าเว็บ รอให้ผ่านเวลาจริงทั้งสองด้านก่อนยืนยัน Final ปกติเป็น 5 นาทีหลังเริ่มเตรียม ไม่จำเป็นต้องรอค้างหน้าจอนี้ ระหว่างนั้นเตรียมข้ออื่นได้

คำสั่งนี้เตรียมคำตอบจำลอง 16 คนผ่านระบบ และคงงานเดิมเมื่อรันซ้ำ ไม่เริ่มห้านาทีใหม่เมื่อเตรียมสำเร็จแล้ว ไม่ใช่การกดประเมินให้ครบทุกคนด้วยมือระหว่างนำเสนอ

**ถ้างานนี้ Final อยู่แล้ว:** ใช้ต่อได้ ถ้าหน้าคะแนนไม่มีช่องยื่นอุทธรณ์เพราะพ้นช่วงเวลา ให้ตรวจตอนซ้อมก่อน ไม่สัญญาว่ารันคำสั่งซ้ำแล้วจะเปิดช่วงอุทธรณ์ใหม่ บท 10 มีทางอธิบายกรณีนี้

### 0.3 เตรียมสิ่งที่จะใช้

- หากจะโชว์ผลงาน ให้เปิด [ชุดผลงานจำลองในเครื่อง](http://localhost:3101/demo-artifacts/index.html) ไว้ในอีกแท็บ และอธิบายว่าเป็นผลงานตัวอย่างที่เตรียมไว้; งานใหม่ที่เว้นช่องลิงก์จะไม่ดึงผลงานของงานเดิมมาให้เอง

- ซูม browser 100% หรือขนาดที่อ่านสบาย ปิดแท็บส่วนตัวและการแจ้งเตือนของโปรแกรมแชต
- เปิดสคริปต์นี้ในอีกหน้าต่าง วางข้าง browser หากต่อโปรเจกเตอร์ให้แชร์เฉพาะหน้าแอป ไม่แชร์หน้าคำสั่งหรือไฟล์ค่าตั้ง
- ซ้อมหนึ่งรอบก่อนวันนำเสนอ เพราะการกดส่ง/ปรับคะแนน/อ่านแจ้งเตือนจะเก็บข้อมูลไว้จริง การเปิดใหม่ไม่ล้างประวัติ

## 1. บทพูดนำก่อนเริ่ม Demo — 3–4 นาที

**เตรียมจอ:** เปิดหน้า 3103 ค้างไว้ ยังไม่เลือกบทบาทและยังไม่เริ่มคลิกสาธิต อ่านบทพูดด้านล่างต่อเนื่องได้เลย ไม่ต้องอ่านหัวข้อย่อยหรือตารางช่วยจำออกเสียง

> สวัสดีครับ วันนี้จะนำเสนอโครงงานชื่อ PairEval ซึ่งเป็นเว็บแอปพลิเคชันสำหรับจัดการการประเมินผลงานแบบเปรียบเทียบเป็นคู่ ใช้กับงานในห้องเรียนที่ต้องการประเมินทั้งผลงานของกลุ่มและการมีส่วนร่วมของสมาชิกแต่ละคน
>
> คำว่าเปรียบเทียบเป็นคู่ หมายถึงผู้ประเมินจะเห็นผลงานสองรายการ เช่น ผลงานกลุ่ม A กับกลุ่ม B แล้วพิจารณาตามเกณฑ์เดียวกันว่าฝั่งใดทำได้ดีกว่าและต่างกันระดับไหน ในระบบนี้เลือกได้ 6 ระดับ จากนั้นระบบจึงรวบรวมคำตอบที่ส่งแล้วไปคำนวณเป็นผลคะแนนตามกติกาของงาน
>

### ตารางช่วยจำ Actor — ใช้ทบทวนก่อนพูด

Actor ในที่นี้หมายถึง **ผู้ที่เข้ามาทำงานกับระบบตามบทบาท** อาจารย์กับนักศึกษาเป็นผู้ใช้หลัก ส่วนอาจารย์ร่วมและ TA ช่วยงานในห้อง บัญชีเดียวกันอาจมีบทบาทต่างกันในแต่ละห้อง

| Actor                           | หน้าที่หลัก                                           | สิ่งที่ใช้แยกให้ผู้ชมเข้าใจ                                                               |
| ------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| อาจารย์เจ้าของห้อง — Owner      | จัดห้อง ทีมผู้สอน งาน รายงาน และยืนยัน/เปิดทบทวนคะแนน | เป็นผู้รับผิดชอบการยืนยันผลของห้อง                                                        |

| ผู้ช่วยสอน — TA                 | จัดรายชื่อและกลุ่ม                                    | ไม่อ่านรายงานคะแนน                                                                        |
| นักศึกษา — Student              | ประเมินงานที่ได้รับ ดูผลตนเอง และขอทบทวน              | ไม่ดูคะแนน/คำขอส่วนตัวของคนอื่น                                                           |
| ผู้ดูแลระดับระบบ — System Admin | จัดสิทธิ์การสร้างห้องเรียนระดับระบบ                   | มีส่วน API แต่ไม่มีหน้าเลือกบทบาท/หน้าจัดการ Admin ในชุดสาธิตนี้ ไม่ต้องหาปุ่มบนหน้า 3103 |

### Main Flow แบบจำสั้น ๆ

**สร้างห้อง/รายชื่อ → สร้างงาน/เกณฑ์ → ตรวจแผน/เผยแพร่ → นักศึกษาประเมินและยืนยันส่ง → คำนวณ/ตรวจรายงาน → ยืนยัน Final → ดูคะแนน/ขอทบทวน**

ถ้ามีการปรับคะแนนหลัง Final: **เปิดทบทวนพร้อมเหตุผล → ปรับคะแนน → ยืนยัน Final ใหม่ → ตอบปิดคำขอ**

การแจ้งเตือน สิทธิ์ และประวัติการทำรายการเป็นส่วนที่สนับสนุนขั้นตอนเหล่านี้ ไม่ต้องหยุดเล่าทุกรายละเอียดก่อนเริ่มคลิก

## 2. อาจารย์เห็นอะไร — 2 นาที

**เปิด/กด:** 3103 → **อาจารย์เจ้าของห้อง** → **เข้าใช้ในบทบาทนี้**

1. ชี้ชื่อบัญชีมุมบนขวา เมนู **ห้องเรียน** และ **ห้องเรียนที่เก็บแล้ว**
2. ในช่องค้นหาห้องเรียน พิมพ์ `สาธิต` ให้เห็นการกรอง แล้วล้างคำค้น
3. เปิดการ์ด **PairEval · สาธิต PRD v2.0** ด้วย **จัดการห้องเรียน**
4. กด **รายชื่อและกลุ่ม** ชี้รายชื่อ รหัสนักศึกษาและกลุ่ม ไม่ต้องอ่านอีเมลทุกคน

**พูด:**

> เมื่อเข้าเป็นอาจารย์ ระบบจะแสดงห้องที่บัญชีนี้มีสิทธิ์ดูแล ในห้องตัวอย่างมีนักศึกษา 16 คน แบ่งเป็น 4 กลุ่ม [รายชื่อและกลุ่มจะใช้กำหนดว่าผู้เรียนมีสิทธิ์ประเมินผลงานใดบ้าง]
>
> ระบบแยกเจ้าของห้อง อาจารย์ร่วม ผู้ช่วยสอน และนักศึกษา หน้าจอและคำสั่งที่แต่ละคนใช้ได้จึงต่างกัน ซึ่งจะสลับให้ดูช่วงท้าย

**เห็นแล้วไปต่อ:** มีตารางรายชื่อ ถ้าจำนวนไม่ใช่ 16 เพราะเคยซ้อมถอนสมาชิก ให้ใช้ห้องใหม่ตามบทถัดไป ไม่บอกตัวเลขผิดจากหน้าจอ


## 3. สร้างห้องและเพิ่มทีมผู้สอน — 4–6 นาที

**เปิด/กด:** เมนู **ห้องเรียน** ด้านบน → กาง **สร้างห้องเรียนใหม่**

1. ชื่อห้อง: ใช้ **ชื่อห้องใหม่ที่จดไว้**
2. เขตเวลา: **Asia/Bangkok · เวลาไทย**
3. ช่อง **รายชื่อนักศึกษา (CSV)**: วางข้อความจากไฟล์ 16 คนที่เตรียมไว้ แล้วกด **สร้างห้องเรียน**
4. เปิดการ์ดห้องใหม่นี้ → **รายชื่อและกลุ่ม** ตรวจว่า 16 คน/4 กลุ่ม ค้นหา `S001` แล้วล้างคำค้น
5. ในส่วน **ทีมผู้สอน** กรอก `v20-presentation-co@example.test` เลือก **อาจารย์ร่วม** → **เพิ่มสมาชิกผู้สอน**
6. ทำอีกครั้งด้วย `v20-presentation-ta@example.test` เลือก **ผู้ช่วยสอน**

**ชี้:** จำนวนคน ตารางกลุ่ม รายการทีมผู้สอน และข้อความทำรายการสำเร็จ

**พูด:**

> อาจารย์เริ่มจากสร้างห้องเรียนและนำเข้ารายชื่อนักศึกษาแบบ CSV  เมื่อสร้างแล้วสามารถค้นหาด้วยชื่อ รหัส หรือกลุ่มได้
> [*สร้างห้องเรียน**ก่อน]
> เจ้าของห้องเพิ่มอาจารย์ร่วมกับผู้ช่วยสอนได้ โดยแต่ละบทบาทมีสิทธิ์ตามหน้าที่ การเพิ่มส่วนนี้เป็นการให้สิทธิ์ในห้องแก่บัญชีที่มีอยู่แล้ว ยังไม่ใช่ระบบส่งคำเชิญทางอีเมล

**ถ้าต้องสาธิต preview รายชื่อ:** กาง **นำเข้าหรือปรับกลุ่มด้วยไฟล์ CSV** วางไฟล์เดิม → **ตรวจข้อมูล** → ชี้ผลเพิ่ม/ย้าย/คงเดิม → **ยืนยันนำเข้ารายชื่อ** บัญชีเดิมไม่ควรกลายเป็นนักศึกษาซ้ำ ทำก่อนเผยแพร่งาน

**ถ้ากรอกผิด/อีเมลไม่มีบัญชี:** อ่านเหตุผลบนจอ แก้เป็นอีเมลตัวอย่างข้างต้นแล้วลองใหม่ ไม่ใช้บัญชีจริงของเพื่อนในรอบนี้

**เครื่องมือรายชื่อในหน้าจัดการงาน:** ห้องที่ยังไม่มีงานก็ตรวจและยืนยันนำเข้ารายชื่อได้ ไม่ต้องสร้าง DRAFT ก่อน หากมีงานเผยแพร่อยู่ในห้องต้องจัดการสถานะงานก่อนจึงนำเข้าได้

## 4. สร้างงานและเผยแพร่คู่ประเมิน — 5–7 นาที

**เปิด/กด:** อยู่ใน **ห้องใหม่** → เมนู **งานประเมิน** → **＋ สร้างงานใหม่**

กรอกตามนี้ ไม่ต้องคิดค่าใหม่ตอนนำเสนอ:

| ช่อง                                                                  | กรอกอะไร                                                                   |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| ชื่องาน                                                               | ชื่องานสดที่จดไว้ เช่น `DEMO-ประเมินโครงงาน-รอบ1`                          |
| คำอธิบาย                                                              | `ข้อมูลจำลองสำหรับสาธิตการประเมินทั้งกลุ่มและรายบุคคล`                     |
| ลิงก์รวมไฟล์ผลงาน                                                     | เว้นว่างได้; ใช้งานเดิมในห้องสาธิตหากต้องการโชว์ไฟล์ผลงานจำลองที่เตรียมไว้ |
| คะแนนกลุ่ม / คะแนนรายบุคคล                                            | `15` / `5`                                                                 |
| กำหนดส่งกลุ่ม / รายบุคคล                                              | วันพรุ่งนี้ เวลา `18:00` ทั้งคู่ ตาม Asia/Bangkok                          |
| ตั้งค่าการจับคู่: ผู้ประเมินต่อคู่ที่ต้องการ / งานสูงสุดต่อผู้ประเมิน | `3` / `8`                                                                  |
| น้ำหนักคำตอบผู้สอน                                                    | `2` (นักศึกษาเท่ากับ 1)                                                    |
| เกณฑ์กลุ่ม                                                            | `ความถูกต้อง` 60% และ `การนำเสนอ` 40%                                      |
| เกณฑ์รายบุคคล                                                         | `การมีส่วนร่วม` 100%                                                       |
| ช่วงคะแนนและสูตรคำนวณ                                                 | คง `0.6` และ `1`                                                           |

**วิธีทำเกณฑ์:** แถวแรกมีมาให้ แก้เป็นกลุ่ม/ความถูกต้อง/60 → กด **เพิ่มเกณฑ์** เป็นกลุ่ม/การนำเสนอ/40 → กด **เพิ่มเกณฑ์** อีกครั้งเป็นรายบุคคล/การมีส่วนร่วม/100 ตรวจว่ารวม **100% แยกแต่ละด้าน**

1. กด **บันทึกฉบับร่าง** รอสำเร็จ
2. กาง **ตรวจแผน เพิ่มผู้ประเมิน และดูประวัติ** ใส่รหัสสุ่ม `demo-live-01`
3. กด **ตรวจความพร้อมการจับคู่**
4. ชี้คำว่า **พร้อมเผยแพร่** ตารางจำนวนคู่/ผู้ประเมินต่อคู่/งานที่แจก
5. กด **เผยแพร่และบันทึกคู่** รอสถานะเปิดรับ/รุ่นการจับคู่

**พูดระหว่างกรอก:**

> งานหนึ่งกำหนดได้ทั้งคะแนนกลุ่มและรายบุคคล ตัวอย่างนี้รวมเต็ม 20 คะแนน เกณฑ์กลุ่มแบ่ง 60 กับ 40 เปอร์เซ็นต์ ส่วนรายบุคคลมีหนึ่งเกณฑ์ 100 เปอร์เซ็นต์ แต่ละด้านมีกำหนดส่งของตัวเอง

**พูดขณะชี้แผน:**

> ก่อนแจกงาน ระบบตรวจว่ามีคนและภาระงานพอสำหรับการจับคู่หรือไม่ อาจารย์ดูจำนวนและข้อควรระวังได้ก่อนยืนยัน รหัสสุ่มช่วยให้ทำซ้ำแผนได้เมื่อใช้ข้อมูลและการตั้งค่าเดิม
>
> เมื่อเผยแพร่ ระบบบันทึกคู่ที่แจกและรุ่นการจับคู่ไว้ นักศึกษาจึงเข้ามาทำงานที่ได้รับได้ การเผยแพร่แล้วจะล็อกการตั้งค่าหลัก ส่วนกำหนดส่งยังขยายตามกฎได้

**เห็นแล้วไปต่อ:** งานสดเป็นเปิดรับ ไม่ใช่ DRAFT หากยังจับคู่ไม่ได้ ตรวจ 16 คน/4 กลุ่ม น้ำหนัก และค่า 3/8 ก่อน อย่ากดเผยแพร่ซ้ำโดยไม่อ่านเหตุผล

## 5. นักศึกษาประเมินกลุ่ม บันทึกร่าง และส่งซ้ำ — 4–6 นาที

**เปิด/กด:** 3103 → **นักศึกษาคนที่ 1** → ห้องใหม่ชื่อเดิม → **ดูงานของฉัน** → การ์ดงานสด → **ประเมินกลุ่ม**

1. ชี้ชื่อเกณฑ์ ผลงาน A/B ความคืบหน้า และกำหนดส่ง
2. ถ้ามี **เปิดผลงาน ↗** เปิดทั้งสองชิ้นแล้วกลับแท็บประเมิน ถ้างานสดไม่มีลิงก์ ให้บอกตามจริงและทำขั้นถัดไป ใช้ผลงานจำลองในห้องเดิมสำหรับโชว์การเปิดไฟล์ได้เมื่อซ้อมไว้แล้ว
3. เลือกคำตอบของคู่แรก เช่น `3` รอข้อความ **บันทึกแล้ว** แล้ว refresh
4. ชี้ว่าตัวเลือกและจำนวนที่ตอบยังอยู่ จากนั้นตอบคู่ที่เหลือตามเกณฑ์ให้ครบในรอบสาธิต จะเลือกต่างกันตามตัวอย่างที่เปิดดูได้
5. กด **ยืนยันส่งคำตอบ** หรือ **ส่งฉบับแก้ไข** หากเคยส่งแล้ว อ่านจำนวนคู่ในกล่อง → ยืนยันด้วยปุ่มในกล่อง
6. ชี้ **ส่งคำตอบแล้ว · ครั้งที่ ...** จดหมายเลขนี้
7. เปลี่ยนหนึ่งคำตอบ รอบันทึก → **ส่งฉบับแก้ไข** → ยืนยัน แล้วชี้ว่าหมายเลขเพิ่ม

**พูด:**

> นักศึกษาเห็นคู่ที่ระบบมอบหมายให้ประเมิน โดยฝั่งกลุ่มจะประเมินคู่ที่ไม่มีกลุ่มตัวเอง ใช้ตัวเลือก 1 ถึง 6 ซึ่งเอนไปทาง A หรือ B ตามระดับ ไม่มีตัวเลือกเสมอ
>
> การเลือกคำตอบจะบันทึกฉบับร่างให้อัตโนมัติ แต่ร่างยังไม่ถือว่าส่ง ต้องกดยืนยันส่งก่อน ระบบจึงนำไปใช้คำนวณ หากยังไม่พ้นกำหนด นักศึกษาแก้และส่งฉบับใหม่ได้ โดยเก็บประวัติฉบับเดิมไว้

**ถ้างานสดไม่มีไฟล์:** สลับไปแท็บชุดผลงานที่เตรียมไว้แล้วพูดว่า “นี่เป็นชุดผลงานจำลองที่เตรียมไว้ให้เห็นตัวอย่าง ระบบรองรับการแนบลิงก์แยกแต่ละกลุ่มหรือบุคคล แต่งานที่เพิ่งสร้างเมื่อครู่ยังไม่ได้ใส่ลิงก์” ดูเสร็จกลับแบบประเมินงานสด ไม่อ้างว่ากดลิงก์จากงานนั้น

**ถ้าเปิดผลงานแล้วหลงแท็บ:** กลับแท็บที่ URL มี `/full-system/assignments/` ไม่ปิดแท็บนั้น

**ถ้าขึ้นอ่านอย่างเดียว:** ตรวจว่าเลือกงานสดในห้องใหม่ ไม่ใช่งานปิดคะแนน เวลาต้องยังไม่หมด

## 6. ประเมินรายบุคคลและดูคะแนนตนเอง — 3–4 นาที

**เปิด/กด:** **กลับไปงานประเมิน** → การ์ดงานสด → **ประเมินรายบุคคล**

1. ชี้ว่าคู่เปลี่ยนเป็นสมาชิกคนอื่นในกลุ่มเดียวกัน ไม่ใช่การให้คะแนนตนเอง
2. เลือกคำตอบแต่ละคู่ รอบันทึก → **ยืนยันส่งคำตอบ** → ยืนยันในกล่อง ให้เห็นครั้งที่ส่งของด้านรายบุคคลจริง
3. กด **ดูคะแนนของฉัน** กาง **คะแนนนี้คำนวณอย่างไร**
4. ชี้คะแนนกลุ่ม รายบุคคล รวม และ **ส่งคำตอบแล้ว ... จาก ... คู่**

**พูด:**

> การประเมินรายบุคคลแยกจากกลุ่ม ต้องส่งคนละด้าน โดยนักศึกษาจะประเมินคู่สมาชิกคนอื่นในกลุ่มตนเอง
>
> หน้าคะแนนแสดงเฉพาะผลของบัญชีนี้ มีองค์ประกอบกลุ่ม รายบุคคล และสัดส่วนงานที่ยืนยันส่ง หากข้อมูลยังไม่พอจะบอกสถานะไว้ ไม่แสดงตัวเลขขึ้นมาเอง และไม่เปิดเผยว่าใครเป็นผู้ประเมินเรา

**ถ้าขึ้น “ข้อมูลยังไม่พอ” หรือ “รอผลประเมิน”:** เป็นไปได้ตามปกติของห้องที่เพิ่งมีคนส่งหนึ่งคน พูดว่า “ห้องนี้เพิ่งเริ่ม จึงยังมีข้อมูลไม่ครบ ต่อไปจะเปิดชุดจำลองที่มีคำตอบหลายคนให้ดูรายงาน” ไม่ปรับคะแนนเพื่อซ่อนสถานะนี้

## 7. รายงาน คะแนน คุณภาพ และไฟล์ส่งออก — 5–7 นาที

### 7.2 เปลี่ยนไปชุดที่มีข้อมูลหลายคน — บอกผู้ชมก่อนเปลี่ยน

**พูดก่อนคลิก:**

**เปิด/กด:** **ห้องเรียน** → **PairEval · สาธิต PRD v2.0** → งาน **ประเมินผลงานโครงงาน — ข้อมูลจำลอง** → **ดูรายงานและคะแนน →**

ถ้างานเดิม Final อยู่แล้ว ให้ดูรายงานที่มีอยู่ ไม่ต้อง Reopen เพื่อช่วงนี้

**ถ้าถามสูตร:** ใช้คำตอบสั้นท้ายเอกสาร ไม่ต้องอธิบายสูตรทั้งหมดในช่วงนี้

## 8. รูประฆังแจ้งเตือน — 2 นาที

**เปิด/กด:** 3103 → **นักศึกษาคนที่ 1** → เข้า **ห้องใหม่/งานสด** → กด **รูประฆัง** ก่อนเมนูบัญชีมุมบนขวา

1. ชี้จำนวนยังไม่อ่าน ข้อความ ชื่อห้อง ชื่องาน และเวลา
2. คลิกการแจ้งเตือน **งานสดในห้องใหม่** ให้เปิดหน้างาน
3. เปิดรูประฆังอีกครั้ง ชี้ว่ารายการนั้นอ่านแล้ว หากมีรายการยังไม่อ่าน กด **อ่านทั้งหมดแล้ว** แล้ว refresh
4. ลอง Escape เพื่อปิด และชี้ว่ากดได้จากหน้างาน ไม่ต้องกลับหน้าแรก

**พูด:**

> การแจ้งเตือนรวมไว้ที่รูประฆัง ใช้ได้ทุกหน้าในพื้นที่ระบบ มีจำนวนรายการที่ยังไม่อ่าน คลิกแล้วไปยังงานหรือผลคะแนนที่เกี่ยวข้องได้
>
> เปิดแผงเฉย ๆ ยังไม่ถือว่าอ่าน ต้องเปิดรายการหรือกดอ่านทั้งหมด ระบบเก็บสถานะอ่านแยกของแต่ละบัญชีไว้

**ถ้าไม่มีตัวเลข:** อาจอ่านครบแล้ว ไม่ใช่ระบบเสีย ใช้แจ้งเตือนที่มีอยู่โชว์ปลายทางได้ ถ้าต้องการรายการใหม่จริง ให้ Owner เผยแพร่งานใหม่แล้วกลับ Student 1 รอโหลดใหม่ ไม่ถอน/เผยแพร่งานหลักซ้ำเพื่อสร้างตัวเลข

ไม่บอกว่าจะมีแจ้งเตือนอุทธรณ์หรืออีเมล เพราะยังไม่ได้เพิ่มเหตุการณ์นั้นในรุ่นนี้

## 9. อาจารย์ยืนยันคะแนน Final — 2–3 นาที

**เปิด/กด:** 3103 → **อาจารย์เจ้าของห้อง** → **ห้องเดิม** → งาน **ตัวอย่างปิดงาน · คะแนนและอุทธรณ์** → **ดูรายงานและคะแนน →**

1. ตรวจว่าผ่านกำหนดส่งจริงของทั้งสองด้านตามที่เตรียมในข้อ 0.2
2. ถ้ายังไม่ Final ให้กด **คำนวณผลระหว่างดำเนินงานใหม่** → **ยืนยันผลคะแนน** → อ่านกล่อง → **ยืนยันผลคะแนน** ในกล่อง
3. ถ้า Final แล้ว ให้ชี้สถานะ **ยืนยันแล้ว** และใช้ต่อ ไม่ต้องกดยืนยันซ้ำ

**พูด:**

> คราวนี้เปลี่ยนมางานตัวอย่างปิดคะแนน ซึ่งเตรียมคำตอบครบและปล่อยให้พ้นกำหนดส่งจริงไว้แล้ว เมื่ออาจารย์ตรวจเสร็จ เจ้าของห้องจึงยืนยันผลเป็น Final ได้
>
> Final เป็นคะแนนที่ยืนยันแล้ว หากต้องแก้ภายหลังต้องเปิดทบทวนพร้อมเหตุผล ไม่แก้ผลเดิมแบบไม่มีประวัติ

**ถ้ายืนยันไม่ได้เพราะเวลา:** ไปบท 11 หรือบทเสริมก่อน แล้วกลับมาเมื่อถึงเวลา ห้ามเปลี่ยนนาฬิกาเครื่องให้ผ่าน

## 10. นักศึกษาอุทธรณ์ → อาจารย์ปรับ → ยืนยันใหม่ — 5–7 นาที

### 10.1 นักศึกษาส่งคำขอ

**เปิด/กด:** 3103 → **นักศึกษาคนที่ 1** → **ห้องเดิม** → งาน **ตัวอย่างปิดงาน · คะแนนและอุทธรณ์** → **ดูคะแนนของฉัน**

1. ชี้ **อาจารย์ยืนยันคะแนนแล้ว** และจดคะแนนรายบุคคล/รวมเดิม
2. เลื่อนลง **ขอทบทวนคะแนน** ใส่เหตุผลต่อไปนี้แล้วกด **ส่งคำขอทบทวนคะแนน**:

> ขอให้ทบทวนคะแนนรายบุคคลจากหลักฐานการทำงานในโครงงานตัวอย่างนี้

หากมีคำขอรอพิจารณาอยู่แล้ว ใช้คำขอเดิม ไม่ต้องส่งซ้ำ

**พูด:**

> หลังยืนยันคะแนน นักศึกษาสามารถแจ้งข้อสงสัยพร้อมเหตุผลผ่านหน้าคะแนนของตนเอง และติดตามคำตอบได้ที่เดียวกัน ไม่เห็นคำขอของนักศึกษาคนอื่น

### 10.2 เจ้าของห้องเปิดทบทวนและปรับคะแนน

**เปิด/กด:** 3103 → **อาจารย์เจ้าของห้อง** → ห้องเดิม → งานปิดคะแนนเดิม → **ดูรายงานและคะแนน →**

1. เลื่อนดู **คำขอทบทวนคะแนน** ชี้ชื่อและข้อความของผู้ยื่น
2. กลับขึ้นส่วนคะแนน กาง **เปิดทบทวนคะแนนที่ยืนยันแล้ว**
3. กรอก **เหตุผลที่เปิดคะแนนใหม่**: `ตรวจคำขอและหลักฐานตัวอย่างเพิ่มเติมก่อนยืนยันผลใหม่`
4. กด **เปิดคะแนนให้แก้ไข**
5. เลื่อนกลับส่วนอุทธรณ์ เลือกคำขอและกรอกคำตอบให้ครบ 10 ตัวอักษร ชี้ว่า **ยืนยัน/ตอบกลับ** กับ **ปฏิเสธพร้อมเหตุผล** ยังใช้ไม่ได้ เพราะยังไม่ Final ใหม่
6. กาง **ปรับคะแนนพร้อมเหตุผล** → ด้าน **รายบุคคล** → รายการ Student 1 (อาจแสดง “นักศึกษาคนที่ 1” หรือ “นักศึกษาจำลอง 1”)
7. คะแนนใหม่ `4.50` จากเต็ม 5 หากเดิมเป็น 4.50 อยู่แล้ว ให้ใช้ `4.25` เพื่อให้เห็นการเปลี่ยน
8. เหตุผล: `ปรับคะแนนจากหลักฐานจำลองที่ตรวจเพิ่มเติมตามคำขอ`
9. กด **บันทึกการปรับคะแนน** ชี้คะแนนฉบับชั่วคราวใหม่ แล้วกด **ยืนยันผลคะแนน** และยืนยันในกล่องอีกครั้ง

**พูด:**

> ผู้สอนเห็นคำขอและตรวจหลักฐานก่อน หากต้องเปลี่ยนคะแนน จะเปิดทบทวนพร้อมเหตุผล แล้วปรับคะแนนเฉพาะส่วนที่เกี่ยวข้อง ระบบสร้างผลฉบับใหม่และเก็บฉบับเดิมไว้
>
> ระหว่างทบทวนจะยังปิดคำขอไม่ได้ ต้องยืนยัน Final ฉบับใหม่ก่อน เพื่อให้คำตอบอุทธรณ์อ้างถึงผลที่ยืนยันแล้ว

### 10.3 ตอบคำขอและกลับไปดูผลนักศึกษา

1. ในรายงาน Final ใหม่ ไปส่วนคำขอ → เลือกคำขอ Student 1
2. คำตอบ: `ตรวจหลักฐานตัวอย่างและปรับคะแนนในผลยืนยันฉบับล่าสุดแล้ว`
3. กด **ยืนยัน/ตอบกลับ** ให้เห็นสถานะ **พิจารณาแล้ว**
4. 3103 → Student 1 → ห้องเดิม → งานปิดคะแนน → **ดูคะแนนของฉัน**
5. ชี้คะแนนรายบุคคลใหม่ สถานะ Final และคำตอบจากอาจารย์ คะแนนรวมอาจต่างจากผลรวมตรง ๆ เมื่อมีตัวคูณ M ให้ดูค่าจริงบนหน้าจอ

**พูด:**

> เมื่อยืนยันผลใหม่แล้ว อาจารย์จึงตอบปิดคำขอได้ นักศึกษาจะเห็นคะแนนล่าสุดกับเหตุผลที่อาจารย์ตอบ ทำให้ติดตามกระบวนการได้ครบ

**ถ้าช่องยื่นคำขอไม่แสดง:** งานต้องเป็น Final และอยู่ในช่วงยื่นอุทธรณ์ 7 วันหลัง Final หากหมดช่วงหรือมีคำขอเดิม ให้โชว์ประวัติที่มีและพูดว่า “ชุดนี้มีผลเดิมอยู่แล้ว จึงแสดงการติดตามคำขอ ส่วนการยื่นใหม่ต้องเตรียมงาน Final ในช่วงเวลาที่ระบบอนุญาต” ไม่กล่าวว่าเพิ่งส่งสำเร็จ

**พูด:**

**บทปิดที่อ่านได้:**

## บทเสริม — ใช้เก็บฟีเจอร์ที่เหลือหรือเมื่อต้องตอบคำถาม

ทำหลังบทหลัก เพื่อไม่เปลี่ยนข้อมูลที่ยังต้องใช้บนเวที บท ก–ค ใช้ **งานสดในห้องใหม่** บท ง–จ ใช้ **ห้องใหม่เท่านั้น** และทำหลังจบการส่ง/คะแนนทั้งหมด

### ก. อาจารย์ประเมินและเพิ่มผู้ประเมิน — 3–4 นาที

**เปิด/กด:** Owner → ห้องใหม่ → งานสดที่ยังเปิดรับ → **ตรวจแผน เพิ่มผู้ประเมิน และดูประวัติ**

1. ใน **คู่และเกณฑ์** เลือกคู่ **กลุ่ม** หนึ่งคู่ ชี้จำนวนผู้ประเมินเดิม
2. **จำนวนผู้ประเมินนักศึกษาเพิ่ม** ใส่ `1` → **เพิ่มผู้ประเมิน** รอข้อความสำเร็จแล้วดูจำนวนใหม่
3. เลือกคู่กลุ่ม → **มอบคู่ให้ตนเอง** → **ประเมินกลุ่ม** เลือกคำตอบ รอบันทึก → ยืนยันส่งในกล่องจริง
4. กลับหน้าเลือกงาน → รายงาน → **คำนวณผลระหว่างดำเนินงานใหม่**

**พูด:**

> ถ้าบางคู่ยังมีข้อมูลไม่พอ ผู้สอนเพิ่มผู้ประเมินได้ตามเงื่อนไข และมอบคู่ให้ตนเองร่วมประเมินได้ ตัวอย่างงานนี้กำหนดน้ำหนักผู้สอนเป็น 2 เทียบกับนักศึกษา 1 ไว้ตั้งแต่ฉบับร่าง

ถ้าไม่มีผู้มีสิทธิ์เหลือ ระบบต้องแจ้งเหตุผล ไม่ใช่แจกเพิ่มได้เสมอ ลองคู่กลุ่มอื่น อย่าเลือกคู่รายบุคคลที่สมาชิกผู้มีสิทธิ์ได้รับครบแล้วเป็นกรณีสำเร็จ หากผู้รับใหม่ไม่ใช่ Student 1/2 ให้โชว์จำนวนและประวัติ ไม่อ้างว่าเปิดแจ้งเตือนของเขาแล้ว

### ข. คุณภาพคำตอบ ตัดออก และคืน — 3 นาที

**เปิด/กด:** Owner → งานสด → รายงาน → **คุณภาพคำตอบ** → **ทบทวนคำตอบที่ส่ง** (งานต้องยังไม่ Final)

1. เลือก **คำตอบที่จะทบทวน** ที่มีในรายการ
2. เหตุผล: `ตัดคำตอบจำลองชั่วคราวเพื่อแสดงขั้นตอนตรวจสอบโดยผู้สอน`
3. กด **ตัดคำตอบออกและคำนวณใหม่** ชี้สถานะ/จำนวนที่ถูกตัด
4. เลือกคำตอบเดิม ใส่เหตุผล `ตรวจคำตอบจำลองแล้วและคืนให้ใช้คำนวณตามเดิม` → **คืนคำตอบและคำนวณใหม่**

**พูด:**

> สัญญาณคุณภาพช่วยชี้จุดให้ผู้สอนตรวจ ส่วนการตัดหรือคืนคำตอบต้องเป็นการตัดสินใจพร้อมเหตุผล ระบบจะคำนวณคะแนนฉบับใหม่ให้ คะแนนอาจไม่เปลี่ยนทุกครั้ง จึงดูสถานะและประวัติร่วมด้วย

หากไม่มีคำตอบในรายการ ให้กลับตรวจว่านักศึกษาหรือผู้สอนยืนยันส่งในงานนี้จริง และกำลังเลือกงานเดียวกัน ไม่ใช้ข้อมูลจากห้องเดิมแทนโดยไม่บอก

### ค. ส่งออกคำตอบและเปิดเผยตัวผู้ประเมิน — 2 นาที

**เปิด/กด:** Owner → รายงานงานที่มีคำตอบ → กาง **ส่งออกคำตอบรายคู่สำหรับตรวจสอบ**

1. กด **ดาวน์โหลดคำตอบดิบแบบรหัสผู้ประเมิน** ชี้ว่าใช้รหัสแทนชื่อ
2. กาง **เปิดเผยตัวผู้ประเมิน (เจ้าของห้องเท่านั้น)**
3. กรอก `ตรวจข้อมูลสังเคราะห์เพื่อสาธิตการส่งออกที่จำกัดสิทธิ์` → **ยืนยันและดาวน์โหลดพร้อมชื่อผู้ประเมิน** → อ่านกล่องและยืนยันเฉพาะข้อมูลจำลอง
4. กาง **ประวัติการทำรายการของห้องเรียน** ชี้เหตุการณ์ล่าสุดและรหัสอ้างอิง เวลาบนตารางและเวลาอัปเดตคะแนนแสดงตามเขตเวลาของห้อง เช่น `Asia/Bangkok` โดยระบุไว้บนหน้าจอ ข้อมูลเวลาภายในยังเก็บเป็น UTC เพื่ออ้างอิงเหตุการณ์เดิม

**พูด:**

> การส่งออกปกติใช้รหัสแทนชื่อผู้ประเมิน ส่วนไฟล์เปิดเผยชื่อและอีเมลจำกัดให้เจ้าของห้อง ต้องระบุเหตุผลและยืนยัน และมีบันทึกการเข้าถึงไว้ ไม่ได้เปิดให้ทุกบทบาทดาวน์โหลด

ถ้าไม่มีเมนูนี้ในเครื่อง ให้บอกว่าเครื่องยังไม่พร้อมสำหรับ export ชนิดนี้และใช้รายงานผลตรวจที่มี ไม่สร้างปุ่มหรือเปิด secret เพื่อแก้สดบนเวที ไฟล์ใหญ่แบบสร้างเบื้องหลังยังไม่ใช่ความสามารถที่ยืนยันจากการดาวน์โหลดไฟล์เล็กนี้

### ง. ขยายกำหนดส่ง คัดลอกงาน เปลี่ยนกลุ่ม และรุ่นการจับคู่ — 4–6 นาที

**เปิด/กด:** Owner → ห้องใหม่ → งานสด

1. **รายละเอียด กำหนดส่ง และเกณฑ์คะแนน** → ขยายเฉพาะกำหนดส่งรายบุคคลเป็นวันถัดไปจากเดิม → **บันทึกกำหนดส่ง** → refresh → เลือกงานเดิม → ชี้ว่าวันรายบุคคลคงอยู่และวันกลุ่มไม่เปลี่ยน
2. กด **คัดลอกเป็นงานใหม่** ให้เห็นงานสำเนา DRAFT ถ้า browser ถามชื่อ ให้ใช้ `DEMO-สำเนางาน-รอบ1` เก็บสำเนาเป็น DRAFT ไม่เผยแพร่เพิ่มในรอบนี้
3. กลับเลือก **งานสดต้นฉบับ** → **ยกเลิกเผยแพร่** ใส่เหตุผล `ปรับกลุ่มข้อมูลจำลองสำหรับสาธิตรุ่นการจับคู่ใหม่` แล้วดำเนินการตามกล่องที่ปรากฏ
4. ไป **รายชื่อและกลุ่ม** → กางนำเข้า CSV ใช้ไฟล์เดิมแต่เปลี่ยนเฉพาะ `group_name` ของ `v20-presentation-s0@example.test` จากกลุ่ม 1 เป็นกลุ่ม 2
5. ตรวจข้อมูล → ชี้สรุปย้าย 1 คน → ยืนยันนำเข้า ถ้ามีงานเผยแพร่อื่นในห้องให้หยุด ระบบต้องไม่ให้เปลี่ยนกลุ่มข้ามข้อจำกัดนี้
6. กลับงานสด DRAFT → ตรวจความพร้อม → เผยแพร่ใหม่ → ชี้ **ประวัติการจับคู่** รุ่นใหม่กับรุ่นที่เก็บประวัติ

**พูด:**

> อาจารย์ขยายกำหนดส่งแยกแต่ละด้านได้ และคัดลอกการตั้งค่าเป็นงานใหม่ได้ หากจะเปลี่ยนกลุ่มหลังแจกงานต้องยกเลิกเผยแพร่ก่อน จากนั้นตรวจแผนและแจกคู่รุ่นใหม่ โดยยังเก็บประวัติเดิม ไม่เอาคำตอบของคู่เก่ามาเป็นคำตอบที่ส่งแล้วของคู่ใหม่

สำหรับงานที่คะแนนรายบุคคลเป็น 0 ช่องกำหนดส่งรายบุคคลจะปิดพร้อมคำอธิบาย ไม่ต้องพยายามกรอกให้ได้; ถ้าจะโชว์ให้ใช้ **งานสำเนา DRAFT** ตั้งรายบุคคล 0 และลบเกณฑ์รายบุคคลแล้วบันทึก ไม่แก้งานต้นฉบับเพื่อกรณีนี้

### จ. ถอดทีมผู้สอน ถอนนักศึกษา และเก็บห้อง — 4–6 นาที

**ส่วนนี้ทำหลังจบทุกการประเมินของห้องใหม่ อย่าทำกับห้องเดิมที่ใช้ Final ตัวอย่าง**

1. Owner → ห้องใหม่ → รายชื่อและกลุ่ม → ทีมผู้สอน → **ถอดออก** ที่อาจารย์ร่วม → อ่านกล่องและยืนยัน
2. สลับ **ผู้สอนร่วม** ที่ 3103 → refresh หน้าห้องเรียน ห้องใหม่ควรหายไปจากรายการที่เข้าถึงได้
3. กลับ Owner → ห้องใหม่ → รายชื่อและกลุ่ม เพิ่มอีเมลอาจารย์ร่วมเดิมกลับด้วยแบบฟอร์ม เพื่อคืนสภาพให้พร้อมซ้อมครั้งถัดไป

**พูด:**

> เจ้าของห้องถอดสิทธิ์ทีมผู้สอนได้ เมื่อถอดแล้วบัญชีนั้นจะเข้าใช้ห้องในบทบาทเดิมไม่ได้ ส่วนประวัติยังอยู่ และเพิ่มบัญชีเดิมกลับได้

4. ถ้าจะโชว์ถอนนักศึกษา: Owner → **งานประเมิน** → กาง **จัดการรายชื่อนักศึกษาและกลุ่ม** → **เครื่องมือทดสอบข้อมูลตัวอย่าง**

**พูด:**

> เครื่องมือข้อมูลจำลองรองรับการถอนสมาชิกพร้อมตรวจการจัดสรรงานปัจจุบัน หากจัดใหม่ไม่ได้ต้องหยุดทั้งรายการ ไม่ปล่อยให้รายชื่อกับงานอยู่คนละสถานะ และยังรักษาประวัติเดิมไว้

7. Owner → หน้าจัดการงานห้องใหม่ → **เก็บห้องเรียนเมื่อจบรายวิชา** → **เก็บห้องเรียน** → ยืนยัน
8. เมนู **ห้องเรียนที่เก็บแล้ว** → เลือกห้องใหม่นี้ → ชี้ข้อมูลย้อนหลัง
9. ถ้าต้องการคืนห้อง ให้ Owner กด **นำห้องกลับมาใช้งาน** และยืนยัน ห้องกลับมาแต่ไม่เริ่มประวัติ/กำหนดส่งใหม่ และไม่เพิ่มนักศึกษาที่ถอนกลับให้อัตโนมัติ

**พูด:**

> เมื่อจบรายวิชา เจ้าของห้องเก็บห้องเป็นข้อมูลย้อนหลังได้ โดยห้องอยู่ในสถานะอ่านอย่างเดียว และนำกลับมาใช้งานได้ตามสิทธิ์ การเก็บห้องไม่ใช่การลบข้อมูลทิ้ง

## ถ้าอาจารย์ถาม — คำตอบสั้นที่อ่านได้

| คำถาม | คำตอบ |
|---|---|
| เปรียบเทียบเป็นคู่คืออะไร? | ให้ดูผลงานสองชิ้นตามเกณฑ์เดียวกัน แล้วเลือกระดับว่าฝั่งใดดีกว่า จากนั้นรวมผลจากหลายคำตอบ |
| ทำไมใช้ 1–6 ไม่มีตรงกลาง? | แบบประเมินรุ่นนี้ใช้ 6 ระดับให้เลือกเอนไปฝั่ง A หรือ B อย่างชัดเจน ไม่ใช่คะแนนชิ้นงานตรง ๆ เต็ม 6 |
| นักศึกษาประเมินตัวเองได้ไหม? | ไม่แจกคู่กลุ่มที่มีกลุ่มตัวเอง ส่วนรายบุคคลเปรียบเทียบสมาชิกคนอื่นในกลุ่มเดียวกัน |
| อัปโหลดผลงานเข้าระบบเลยไหม? | รุ่นนี้อาจารย์ใส่ลิงก์รวมและลิงก์ผลงานรายกลุ่ม/บุคคล ระบบเปิดผลงานผ่านลิงก์ ไม่ได้สาธิตบริการอัปโหลดไฟล์เก็บในแอป |
| q คืออะไร? | ค่าสรุปจากผลเปรียบเทียบของผลงานในเกณฑ์นั้น ใช้ช่วง 0 ถึง 1 ไม่ใช่คะแนนเต็มของงานโดยตรง |
| คะแนนคิดอย่างไร? | ต่อเกณฑ์ใช้คะแนนเต็มของด้าน × น้ำหนักเกณฑ์ × (floor + (ceiling − floor) × q) แล้วรวมองค์ประกอบกลุ่ม/รายบุคคลและคูณ M ตามสัดส่วนงานที่ส่ง |
| ยกตัวอย่างง่าย ๆ ได้ไหม? | ตัวอย่างสมมติ Group เต็ม 15 เกณฑ์เดียว 100%, q=0.5 และช่วง 0.6–1 จะได้ 12; Individual เต็ม 5 เงื่อนไขเดียวกันได้ 4 ถ้า M=1 รวม 16 ตัวอย่างนี้ไม่ใช่ตัวเลขบังคับของทุกงาน |
| p และ M คืออะไร? | p คือสัดส่วนคำตอบที่ยืนยันส่งตามขอบเขตของงาน ค่าเริ่มต้นส่งอย่างน้อย 90% ได้ M=1 ถ้าต่ำกว่านั้น M=p÷0.9 ฉบับร่างไม่นับเป็นการส่ง |
| ทำไมข้อมูลไม่พอทั้งที่ส่งแล้ว? | ส่งของเราอย่างเดียวไม่ได้แปลว่ามีผู้ประเมินงานเราเพียงพอ และระบบยังมีเงื่อนไขจำนวนข้อมูลเพื่อปกป้องผู้ประเมิน จึงต้องดูสถานะ ไม่เติม 0 แทนข้อมูลที่ไม่มี |
| Interim กับ Final ต่างกันอย่างไร? | Interim คือคะแนนระหว่างดำเนินงาน ยังเปลี่ยนได้ ส่วน Final คือฉบับที่เจ้าของห้องยืนยันแล้ว ต้องเปิดทบทวนพร้อมเหตุผลเมื่อต้องแก้ |
| Snapshot คืออะไร? | คะแนนฉบับหนึ่ง ณ เวลาคำนวณพร้อมข้อมูลอ้างอิง ใช้รู้ว่ารายงานและไฟล์ส่งออกมาจากผลชุดไหน |
| QS บอกได้เลยว่าใครโกงไหม? | ไม่ได้ เป็นสัญญาณช่วยตรวจ ต้องดูจำนวนข้อมูลและบริบท ผู้สอนพิจารณาพร้อมเหตุผล ไม่หักคะแนนอัตโนมัติ |
| ถ้ากลุ่มเล็กหรือจับคู่ไม่ได้? | กลุ่มไม่เกิน 2 คนไม่เปิดประเมินรายบุคคล กลุ่ม 3 คนมีคำเตือนความเชื่อมั่นต่ำ และห้องที่มีเพียง 2 กลุ่มยังติดข้อจำกัดการแจกคู่ Group ต้องระบุข้อจำกัดนี้ |
| อุทธรณ์ทุกครั้งต้องแก้คะแนนไหม? | ไม่จำเป็น หากอธิบายผลเดิมบน Final ปัจจุบันก็ตอบได้ แต่ถ้าเปิดทบทวนและแก้คะแนนแล้วต้อง Final ใหม่ก่อนปิดคำขอ |
| ใช้กับคนจริงได้ทันทีไหม? | รุ่นนี้ส่งมอบเป็นต้นแบบ local ใช้ข้อมูลจำลอง ยังต้องจัด OAuth นโยบายข้อมูล deploy และตรวจ production เพิ่มก่อนใช้กับข้อมูลหรือคะแนนจริง |
| ฟีเจอร์ครบ PRD ทุกข้อไหม? | มีเส้นทางหลักของต้นแบบตามที่สาธิต ส่วนรายข้อมีผ่านบางส่วนและงานที่เลื่อนไว้ ดู Evidence map ไม่ใช้จำนวน tests หรือการคลิกจบแทนการผ่าน PRD ทั้งหมด |

## ถ้าติดกลางทาง — ทำตามนี้ก่อน

| อาการ | ไปต่ออย่างไร |
|---|---|
| เปิด 3101 แล้วเห็นปุ่ม Google | กลับ 3103 แล้วเลือกบทบาท ไม่ต้องกรอก OAuth เพื่อสาธิตรอบนี้ |
| เมนูไม่เหมือนในบท | ดูชื่อบัญชีมุมขวาก่อน แล้วเลือกบทบาทใหม่ที่ 3103 และ refresh |
| หาเมนูไม่เจอ | หลายส่วนอยู่ใต้หัวข้อที่กางได้ เลื่อนดูและคลิกชื่อหัวข้อก่อน เช่น “ตรวจแผน เพิ่มผู้ประเมิน และดูประวัติ” |
| คำตอบ/คะแนนไม่ใช่ที่เพิ่งทำ | ตรวจชื่อห้องกับงาน: งานสดอยู่ห้องใหม่; งาน Final และรายงานพร้อมข้อมูลอยู่ห้องเดิม |
| คะแนนยังไม่ขึ้น | ยืนยันส่งทั้งสองด้านก่อน แล้ว Owner คำนวณใหม่ในงานเดียวกัน หากยังไม่พอแสดงสถานะจริง ใช้ชุดที่เตรียมไว้โชว์รายงาน |
| คู่ประเมินเดิมเป็นอ่านอย่างเดียว | อาจพ้น deadline หรือกำลังดูงานปิดคะแนน ใช้งานสดที่กำหนดส่งพรุ่งนี้ |
| ปุ่ม Final ไม่ผ่าน | ตรวจว่าเป็น Owner ผ่านกำหนดส่งทั้งสองด้าน และมีผลคำนวณแล้ว หากยังไม่ถึงเวลาให้สาธิตหัวข้ออื่นก่อน |
| ปุ่มตอบอุทธรณ์ใช้ไม่ได้ | ต้องเลือกคำขอ กรอกอย่างน้อย 10 ตัวอักษร และ Final ฉบับล่าสุดก่อน ถ้าจะปรับคะแนน ให้ใช้ “ปรับคะแนนพร้อมเหตุผล” ไม่พิมพ์คะแนนในช่องคำตอบ |
| สร้างห้องแล้ว Student 1 ไม่เห็น | CSV ต้องใช้อีเมล `v20-presentation-s0@example.test` ตามไฟล์ตัวอย่าง ไม่ใช่อีเมลนักศึกษาที่พิมพ์ขึ้นใหม่ |
| แจ้งเตือนว่าง | ต้องเป็นบัญชีผู้รับและมีเหตุการณ์ที่เข้าถึงได้ Owner/Co/TA ไม่ได้มีรายการเหมือน Student; สร้าง/เผยแพร่งานใหม่เพื่อให้มีเหตุการณ์ใหม่เมื่อจำเป็น |
| ไฟล์โหลดแล้วหาไม่เจอ | เปิด Downloads ของ browser หรือโฟลเดอร์ Downloads ของ Windows ชื่ออาจมี `(1)` หากโหลดซ้ำ |
| โหลดไม่สำเร็จ/ถูกจำกัดการเรียก | หยุดกดถี่ รอตามข้อความแล้วกดลองใหม่หนึ่งครั้ง หากยังผิด เก็บภาพและจดบทบาท/ห้อง/งาน ไม่กดทำรายการซ้ำรัว ๆ |

ถ้าติดจริงและไปต่อไม่ได้ ใช้ประโยคนี้: “ขั้นนี้มีปัญหาในรอบสาธิต ขอจดไว้ตรวจเพิ่มเติม ต่อไปจะแสดงส่วนที่เตรียมไว้แล้ว” ไม่บอกว่าผ่านหากยังไม่เห็นผล

## หลังสาธิตจบ

1. จดว่าห้องใหม่ชื่ออะไร งานไหน Final คำขอไหนปิดแล้ว มีใครถูกถอด/ถอน เพื่อให้ซ้อมรอบถัดไปไม่สับสน
2. ถ้าจะเริ่มเรื่องจากศูนย์รอบหน้า ให้สร้าง **ห้องใหม่ชื่อรอบใหม่** เก็บข้อมูลรอบเก่าไว้ ไม่ใช้ `seed:reset` กับ Full System
3. หยุดชุดที่เปิดอยู่ด้วยคำสั่งต่อไปนี้ในโฟลเดอร์ชุดนั้น ข้อมูลที่บันทึกแล้วคงอยู่:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-PairEval-Demo.ps1
```
