# แบบบันทึกผลทดสอบ UI ด้วยตนเอง — PairEval

คัดลอกไฟล์นี้ก่อนกรอก เช่น `manual-ui-ชื่อ-วันทดสอบ.md` ใช้คู่กับ [คู่มือ MANUAL_UI_TEST](../MANUAL_UI_TEST.md) ซึ่งระบุขั้นตอน/ผลที่คาดของแต่ละ ID กด Ctrl+F ค้นหา ID เพื่อไปกรณีนั้น

ไฟล์นี้เป็นแบบฟอร์มเปล่า ค่า NOT RUN เป็นค่าเริ่มต้น ไม่ใช่รายงานว่ามีผู้ทดสอบรอบนี้แล้ว กรุณาเก็บผลแต่ละคน/แต่ละรอบแยกไฟล์

## 3. สรุปผลที่ทำจริง

| สถานะ | จำนวนกรณี |
|---|---:|
| PASS — ทำครบและตรงตามคาด | |
| FAIL — ผลไม่ตรงตามคาด | |
| BLOCKED — ขาดเงื่อนไข/fixture ระบุเหตุผลรายข้อ | |
| NOT RUN — ยังไม่ได้ลอง | |
| รวม | 98 |

### ข้อสรุปจากผู้ทดสอบ

- เส้นทางที่ทำสำเร็จจนจบ:
- ปัญหาที่กระทบการสาธิต/สิทธิ์/ข้อมูล/คะแนน:
- ข้อที่ต้องให้ผู้พัฒนาจัดข้อมูลหรือช่วยตรวจ:
- ความสะดวก/ข้อความหรือเมนูที่ทำให้สับสน:
- ผลปิด–เปิดใหม่:
- สถานะสุดท้ายของห้อง/บัญชีที่เปลี่ยนระหว่างทดสอบ:

## 5. รายงานปัญหา — คัดลอกหนึ่งชุดต่อปัญหา

```text
BUG-ID:
เกี่ยวข้องกับ test case ID:
รุ่นที่ใช้จริง / browser:
บทบาท / ชื่อห้อง / ชื่องาน:
หน้า URL (ไม่ใส่ cookie/token):
เงื่อนไขก่อนเกิด: สถานะงาน / snapshot / deadline / จำนวนสมาชิก
ขั้นตอนทำซ้ำ:
1.
2.
3.
ข้อมูลสังเคราะห์ที่กรอก:
ผลที่คาด:
ผลที่เกิดจริง / ข้อความผิดพลาดตามหน้าจอ:
เกิดซ้ำกี่ครั้งจากที่ลองกี่ครั้ง:
ผลหลัง refresh หรือปิด–เปิด:
ภาพประกอบ / ชื่อไฟล์ผลลัพธ์ที่เก็บไว้:
ผลกระทบ: ทำต่อไม่ได้ / คะแนนผิด / สิทธิ์รั่ว / ข้อมูลหาย / ข้อความหรือความสะดวก
```

ส่งเฉพาะข้อมูลจำเป็นและภาพที่ตัดข้อมูลส่วนตัวออก ไม่ส่ง `.env.local`, cookie/token, `.verification` ทั้งชุด, ฐานข้อมูล, backup/key หรือไฟล์สำเนาข้อมูลส่วนตัวทั้งชุด
