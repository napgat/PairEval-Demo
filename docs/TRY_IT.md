# รายการลองใช้งานสำหรับเพื่อน

ใช้เวลาประมาณ 20–30 นาทีหลังติดตั้ง [ตามคู่มือ](GETTING_STARTED.md) ทุกกรณีใช้ข้อมูลสมมติ บันทึกว่าทำจริงข้อไหนและผลเป็นอย่างไร ไม่ถือว่าข้อที่ข้ามผ่านแล้ว

## เตรียม

1. บันทึก `git rev-parse --short HEAD`, Windows/Node/browser ที่ใช้ ถ้าโหลด ZIP ให้ระบุวันที่และสาขา
2. เปิด 3103 แล้วเตรียม `npm run demo:prepare-final` ไว้ตั้งแต่ต้นหากจะลอง Final
3. แต่ละบทบาทเลือกได้ที่ 3103 การสลับบทบาทเปลี่ยน session ของ browser profile นั้นทั้งหมด

## A. อาจารย์จัดการห้องและงาน

- [ ] Owner เข้าห้องสาธิต เห็นนักศึกษา 16 คน/4 กลุ่ม และเปิดรายงานงานหลักได้
- [ ] ลอง **สร้างห้องเรียนใหม่** โดยใช้ชื่อ/อีเมลสมมติ ใช้ [CSV สมมติของ Full System](../examples/full-system-roster.csv) ตรวจหน้าตัวอย่าง roster ก่อนยืนยัน อย่าใช้ไฟล์รายชื่อจริง
- [ ] สลับ Co-teacher/TA ที่เตรียมไว้จากหน้า 3103 ตรวจสิทธิ์ในห้องสาธิตตามหัวข้อ D; การเพิ่ม–ลบผู้สอนมี API แต่ **สาย v2.0 นี้ยังไม่มีแบบฟอร์ม GUI** จึงไม่อ้างว่าทดสอบเพิ่ม–ลบผ่านหน้าจอได้
- [ ] สร้างงาน DRAFT ในห้องสาธิต ตั้งคะแนน/เกณฑ์/กำหนดส่ง → ตรวจความเป็นไปได้ → เผยแพร่คู่ประเมิน อย่าแก้หรือลบงานตัวอย่างเดิมเพื่อซ้อม
- [ ] ลองเกณฑ์น้ำหนักรวมผิดหรือห้องที่นักศึกษาไม่พอ ระบบต้องแจ้งเหตุผลและไม่เผยแพร่งานบางส่วน
- [ ] ลองขยาย deadline ของงานที่สร้างใหม่ เวลาที่แสดงต้องตรงกับ timezone ห้องเรียน
- [ ] ด้านที่คะแนนเต็ม 0 ต้องไม่ให้แก้ deadline; ถ้าใช้ทั้งสองด้าน ให้ลองขยาย Individual โดยไม่เปลี่ยน Group แล้วเปิดใหม่ตรวจค่าที่บันทึก

การสร้างห้องใหม่จะไม่มีนักศึกษาจากห้องเก่าตามไปเอง ถ้าจะลอง publish ให้เตรียม roster ที่มีขนาดพอ หรือใช้ห้องสาธิตที่มีชุดพร้อมอยู่แล้ว

## B. นักศึกษาประเมินทั้งสองด้าน

- [ ] เลือกนักศึกษาคนที่ 1 → ห้องสาธิต → งานหลัก → Group เปิดผลงานและเลือกคำตอบบางคู่
- [ ] รอข้อความบันทึกร่างแล้ว refresh คำตอบต้องคงอยู่
- [ ] ส่งคำตอบ อ่านจำนวนคู่ที่ยังไม่ตอบและยืนยัน ต้องเห็น revision ที่ส่ง
- [ ] แก้คำตอบและส่งใหม่ก่อน deadline ต้องได้ revision เพิ่ม ประวัติเดิมยังอยู่
- [ ] ทำเส้นทางเดียวกันใน **Individual** จนส่งจริง ไม่ใช่เพียงเปิดหน้า
- [ ] เปิดคะแนนของฉัน เห็นเฉพาะผลตนเอง สลับเป็นนักศึกษาคนที่ 2 แล้วตรวจว่าข้อมูลเป็นของคนที่ 2

ฉบับร่างไม่นับเป็นการส่ง หากส่งบางส่วน คะแนนการมีส่วนร่วมอาจยังไม่เต็ม ให้ดูจำนวนคู่ที่ส่งตามจริง

## C. รายงานและไฟล์ส่งออก

- [ ] กลับ Owner → งานหลัก → รายงาน → คำนวณผลระหว่างดำเนินงานใหม่
- [ ] ตรวจ 4 แท็บ: กลุ่ม รายบุคคล ความครอบคลุมคู่ และคุณภาพคำตอบ ไม่มีข้อความผิดพลาด
- [ ] ดาวน์โหลด CSV และ Excel เปิดไฟล์ได้ ตรวจจำนวน 16 นักศึกษาและคะแนนตรงหน้ารายงาน ณ snapshot เดียวกัน
- [ ] การคำนวณใหม่หลังเปลี่ยนคำตอบอาจทำให้คะแนนเปลี่ยน ต้องเทียบไฟล์ที่มาจาก snapshot เดียวกัน ไม่เทียบไฟล์เก่ากับ UI ใหม่

การเปิด Excel อาจปัดจำนวนทศนิยมต่างจากหน้าจอ ให้เทียบค่าที่ปัดระดับเดียวกัน การตรวจสูตรอิสระทั้งชุดเป็นงานเพิ่มของผู้พัฒนา ไม่ควรสรุปจากเพียงไฟล์เปิดได้

## D. Final → อุทธรณ์ → ทบทวน

- [ ] รอ deadline จริงของงาน `ตัวอย่างปิดงาน · คะแนนและอุทธรณ์` → Owner คำนวณ Interim ล่าสุด → ยืนยันผลคะแนน
- [ ] นักศึกษาคนที่ 1 เปิดคะแนน Final → ยื่นคำขอทบทวนพร้อมเหตุผลสมมติอย่างน้อย 20 ตัวอักษร
- [ ] Owner เปิดทบทวนคะแนนพร้อมเหตุผลอย่างน้อย 10 ตัวอักษร → ปรับคะแนนรายบุคคลของนักศึกษาคนที่ 1 เป็น 4.50 พร้อมเหตุผล → ยืนยัน Final ฉบับใหม่ → ตอบคำอุทธรณ์
- [ ] หลัง Reopen และหลังปรับคะแนนเป็น Interim ปุ่มตอบ/ปฏิเสธอุทธรณ์ต้องยังใช้ไม่ได้ จนกว่าจะยืนยัน Final ใหม่
- [ ] นักศึกษาเห็นผลฉบับใหม่และคำตอบอาจารย์ คะแนนรวมต้องตรงองค์ประกอบกลุ่ม + รายบุคคลตามกติกา ไม่ใช้ 16.94 เป็นค่าคงที่ของเครื่องใหม่
- [ ] การแจ้งเตือนเปิดไปยังงาน/คะแนนที่เกี่ยวข้องได้

Owner เท่านั้นที่ยืนยัน/เปิดทบทวนคะแนน ผู้สอนร่วมไม่ควรเห็นปุ่มนี้ TA ไม่ควรอ่านรายงานคะแนน นักศึกษาไม่ควรเห็นรายงานของอาจารย์ ทดสอบเปิด URL เดิมหลังสลับบทบาทด้วย ผลต้องถูกปฏิเสธหรือไม่แสดงข้อมูล

## E. ความสะดวกและข้อมูลคงอยู่

- [ ] ใช้ Tab/Shift+Tab เลือกปุ่มและแบบฟอร์ม เห็นตำแหน่ง focus; Esc ปิด dialog และคืน focus
- [ ] ลองหน้าจอแคบประมาณ 390 px ข้อความ/ปุ่มสำคัญไม่ถูกบัง ตารางเลื่อนในกรอบได้
- [ ] หยุดด้วย Stop script → เปิดใหม่ ข้อมูลที่ส่ง คะแนน Final และคำอุทธรณ์ยังอยู่

## ตรวจด้วย browser อัตโนมัติ (ทางเลือกสำหรับคนเขียนโค้ด/AI)

ขณะชุดสาธิตเปิดอยู่:

```powershell
npx playwright install chromium
npm run test:demo-ui
```

ตรวจหน้าหลัก desktop/mobile, role, keyboard/focus, dialog, overflow และ Axe โดยไม่ยืนยันส่งคำตอบหรือ Final ให้เอง สคริปต์อ่าน ID จากชุดสาธิตของเครื่องนั้น ไม่ฝังคะแนน 16.94 หากยังไม่มี Final จะแจ้งข้ามส่วน Final ชัดเจน ผล/ภาพอยู่ใน `.verification/ui-usability-20261016/` และมีข้อมูลสังเคราะห์ที่ไม่ควรยกทั้งโฟลเดอร์เข้า Git

การผ่านเครื่องมือไม่ได้ทดแทนการลอง A–E หรือรับรอง WCAG ทุกข้อ

## รายงานผลกลับ

คัดลอกหัวข้อนี้แล้วกรอก ส่งให้เจ้าของโครงงานด้วยช่องทางที่ตกลงกัน:

```text
Commit/ZIP และวันที่:
Windows / Node / browser:
ติดตั้งจากเครื่องว่างหรืออัปเดต:
ข้อที่ลองจริง: A... B... C... D... E...
ข้อที่ข้ามและเหตุผล:
ปัญหาที่พบ:
  บทบาท/หน้า:
  ขั้นตอนทำซ้ำ (1, 2, 3):
  สิ่งที่คาดว่าจะเกิด:
  สิ่งที่เกิดจริง/ข้อความผิดพลาด:
  ภาพประกอบ (ตัดข้อมูลส่วนตัวออก):
ผลหลังปิด–เปิดใหม่:
ข้อเสนอแนะด้านการใช้งาน:
```

ไม่แนบ `.env.local`, token/cookie, `.verification` ทั้งชุด, ฐานข้อมูล หรือ backup/key ถ้าต้องส่ง log ให้ตัด credential และพาธส่วนตัวออกก่อน
