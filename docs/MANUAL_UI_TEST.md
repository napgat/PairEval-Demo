# คู่มือทดสอบด้วยตนเองผ่าน UI — PairEval Full System

สำหรับเจ้าของโครงงานและเพื่อนผู้ทดสอบ · ปรับปรุง 17 ตุลาคม 2026 · รวมการย้ายแจ้งเตือนขึ้น navbar หลังรุ่น `bb0fbf9`

คู่มือนี้ครอบคลุมหน้าจอและการทำงานที่มีใน Full System รุ่นปัจจุบัน ใช้ข้อมูลสังเคราะห์บนเครื่องของแต่ละคน อ้างอิง PRD v2.0 ส่วนผลตรวจรับ PRD รายข้อดู [Evidence map](full-system/prd-v2.0-evidence-map.md) การมีกรณีทดสอบในคู่มือนี้ **ยังไม่ใช่ผลว่าทดสอบผ่านแล้ว**

## วิธีใช้คู่มือ

1. ติดตั้งหรืออัปเดตตาม [GETTING_STARTED](GETTING_STARTED.md) แล้วเปิด `http://localhost:3103`
2. คัดลอก [แบบบันทึกผล](testing/MANUAL_UI_RESULTS_TEMPLATE.md) ตั้งชื่อใส่ชื่อผู้ทดสอบและวันที่ เช่น `manual-ui-napat-2026-10-17.md` เก็บผลของแต่ละคนแยกกัน
3. บันทึกรุ่น/เครื่อง/browser แล้วทำตามลำดับด้านล่าง แต่ละกรณีมี ID ให้ใช้แจ้งปัญหา
4. กรอกผล **PASS / FAIL / BLOCKED / NOT RUN** และหลักฐานในแบบบันทึก ห้ามถือว่าข้อที่ข้ามผ่านแล้ว
5. ใช้ mouse/keyboard คลิกจริง ไม่เรียก API, แก้ฐานข้อมูล หรือเปลี่ยนนาฬิกาเพื่อให้ผ่านกรณีทดสอบ การติดตั้งและเตรียมข้อมูลเป็นขั้นตอนก่อนทดสอบที่แยกไว้ชัดเจน

คู่มือมี **100 กรณี** แยกตามรหัสหมวด เช่น STA = ทีมผู้สอน, EXP = ส่งออก, APL = อุทธรณ์ ใช้ Ctrl+F ค้นหา ID จากแบบบันทึกได้ กรณีในหมวด “ข้อมูลพิเศษ” ทำหลังงานหลัก; ถ้าขาด fixture ให้บันทึก BLOCKED ตามเงื่อนไข

ผล browser automation ก่อนเปลี่ยน navbar: [98/98 หลังแก้และตรวจซ้ำ 17 ต.ค.](testing/MANUAL_UI_98_RESULTS_2026-10-17.md) ใช้ source ตั้งต้น `8c33107` และการแก้ใน `bb0fbf9`; การแจ้งเตือนรุ่นใหม่ดู [ผลตรวจแยก](testing/NOTIFICATION_BELL_2026-10-17.md) ยังไม่อ้างว่ารันคู่มือฉบับ 100 กรณีใหม่ทั้งหมด เก็บผลแต่ละคนแยกกัน ไม่กรอก PASS แทนการลองบนเครื่องตนเอง

**ความหมายของผล:** PASS = ทำครบและได้ผลตามคาด; FAIL = ทำแล้วผิดจากที่คาด; BLOCKED = ทำต่อไม่ได้เพราะขาดข้อมูล/เงื่อนไข ให้บอกสาเหตุ; NOT RUN = ยังไม่ได้ลอง

ถ้าข้อก่อนหน้าล้มเหลวจนทำข้อถัดไปไม่ได้ ให้กรอกข้อแรกเป็น FAIL และข้อที่ทำต่อไม่ได้เป็น BLOCKED พร้อมอ้าง ID ต้นเหตุ อย่าล้างฐานหรือแก้ข้อมูลหลังบ้านเพื่อข้ามข้อผิดพลาดนั้น

### เลือกรอบทดสอบ

| รอบ | รายการ | เวลาประมาณหลังติดตั้ง |
|---|---|---|
| ตรวจเร็ว | SET-01–04, NAV-01–02, STA-01–04, EVG-01–05, EVI-01–03, RPT-01–02, EXP-01, UX-01 | 30–45 นาที ใช้ห้องสาธิต/ห้องทีมผู้สอนตามเงื่อนไข |

| ตรวจสองปัญหาเดิม | กำหนดส่งและอุทธรณ์ตาม [PEER_RETEST](PEER_RETEST.md) | 15–25 นาที ขึ้นกับข้อมูลที่เตรียม |

## 1. เตรียมเครื่อง บัญชี และข้อมูล

### 1.1 เปิดระบบ

ติดตั้งครั้งแรกตาม GETTING_STARTED: Windows x64, Node.js 24, โฟลเดอร์พาธภาษาอังกฤษ, `npm ci` และ `npm run build` จากนั้นดับเบิลคลิก `Open-PairEval-Demo.cmd` เปิดครั้งละหนึ่งชุดในเครื่อง เพราะใช้ port เดียวกัน

บันทึก commit ด้วย `git rev-parse --short HEAD` หากใช้ ZIP ให้บันทึกชื่อ ZIP/วันที่แทน ตัวติดตั้งเตรียมฐานและค่าตั้งให้เอง ไม่ต้องขอ Google/Neon secret หรือคัดลอก `.env.local` จากผู้อื่น

| บทบาทที่เลือกหน้า 3103 | บัญชีสังเคราะห์ | ใช้ทดสอบ |
|---|---|---|
| อาจารย์เจ้าของห้อง | `v20-presentation-owner@example.test` | สร้างห้อง จัดทีมผู้สอน งาน รายงาน Final และเก็บห้อง |
| ผู้สอนร่วม | `v20-presentation-co@example.test` | จัดงาน ประเมินในฐานะผู้สอน และอ่านรายงาน |
| ผู้ช่วยสอน | `v20-presentation-ta@example.test` | จัดรายชื่อและกลุ่ม |
| นักศึกษาคนที่ 1 | `v20-presentation-s0@example.test` | Group/Individual คะแนน อุทธรณ์ |
| นักศึกษาคนที่ 2 | `v20-presentation-s1@example.test` | เปรียบเทียบสิทธิ์/ข้อมูลระหว่างนักศึกษา |

ชื่อในบางห้องอาจเป็น “นักศึกษาจำลอง 1/2” ตาม CSV ให้ใช้อีเมลยืนยันว่าเป็นบัญชีเดียวกัน การเปลี่ยนบทบาทที่ 3103 เปลี่ยน session ของทุกแท็บใน browser profile เดียวกัน ถ้าจะเปิดสองบทบาทพร้อมกัน ใช้คนละ browser profile

### 1.2 ชุดข้อมูลที่ใช้และลำดับการเปลี่ยนข้อมูล

| ชื่อเรียกในคู่มือ | เตรียมอย่างไร | ใช้เมื่อ |
|---|---|---|
| ห้องสาธิตเดิม | Launcher เตรียม `PairEval · สาธิต PRD v2.0` มี 16 นักศึกษา/4 กลุ่ม พร้อมงานหลักและคำตอบจากบัญชีอื่น | รอบตรวจเร็วและรายงานที่มีข้อมูลอยู่แล้ว |
| ห้อง UI หลัก | Owner สร้างชื่อ `UI-ชื่อผู้ทดสอบ-วันเวลา` วาง CSV ทั้งไฟล์จาก [full-system-roster.csv](../examples/full-system-roster.csv) ได้ 16 นักศึกษา/4 กลุ่ม | CLS, STA, ASN, EVG, EVI, TEA, RPT, EXP และ NOT |
| ห้องเปลี่ยนกลุ่ม | สร้างแยกด้วย CSV 16 คนชุดเดียวกัน ชื่อขึ้นต้น `UI-เปลี่ยนกลุ่ม-` และมีงาน OPEN เพียงงานเดียว | CHG |
| ห้องถอนสมาชิก | สร้างแยกด้วย CSV 16 คนชุดเดียวกัน ชื่อขึ้นต้น `UI-ถอนสมาชิก-` มีงาน OPEN ที่ยังไม่ Final และเพิ่ม TA ตาม STA-02 ไว้ก่อนเก็บห้อง | WDR และ ARC หลังทดสอบถอนเสร็จ |
| งาน Final ตัวอย่าง | ขณะบริการเปิด รัน `npm run demo:prepare-final` ในโฟลเดอร์แอป แล้วรอ deadline จริง 5 นาที งานชื่อ `ตัวอย่างปิดงาน · คะแนนและอุทธรณ์` อยู่ในห้องสาธิตเดิม | SCR และ APL |

เปิดไฟล์ CSV เป็นข้อความแล้วคัดลอกทั้งหัวตารางและทุกรายการลงช่อง CSV หน้าเว็บ รุ่นนี้ใช้ช่องวางข้อความ ไม่ใช่ปุ่มอัปโหลดไฟล์ ห้ามนำข้อมูลนักศึกษาจริงมาใช้

คำสั่งเตรียม Final เป็นการเตรียม fixture ผ่านระบบก่อนเริ่มตรวจด้วยมือ ไม่ถือเป็นการคลิกทดสอบ Final/อุทธรณ์ ผู้ทดสอบต้องทำขั้นตอน SCR/APL เอง การรันซ้ำเก็บงานเดิมไว้ ไม่รีเซ็ตหรือเริ่มนับ 5 นาทีใหม่เมื่อเตรียมสำเร็จแล้ว

**งานหลักมีอายุเปิดรับ 7 วันนับจากเตรียมครั้งแรก** ถ้าหมดเขตแล้ว ให้สร้างงานใหม่ในห้อง UI หลักเพื่อทดสอบร่าง/ส่งซ้ำ เก็บงานเดิมไว้อ่านย้อนหลัง

## 8. เพิ่มผู้ประเมินและอาจารย์ประเมิน

ทำในงาน OPEN ห้อง UI หลักก่อนหมดเวลา โดยเลือกคู่ **Group** ซึ่งยังมีนักศึกษาที่ไม่ได้รับคู่นั้น ไม่ใช้คู่ Individual ที่แจกผู้มีสิทธิ์ครบแล้วเป็นกรณีสำเร็จ

| ID | บทบาท / ขั้นตอน | ผลที่ควรได้ |
|---|---|---|
| TEA-01 | Owner เลือกงาน → การจับคู่และผู้ประเมิน เลือก “คู่และเกณฑ์” ใส่จำนวน 1 → เพิ่มผู้ประเมิน | สำเร็จแล้วจำนวนผู้ประเมินของคู่เพิ่ม ไม่แจกซ้ำให้คนเดิม หากไม่มีผู้มีสิทธิ์เหลือต้องแจ้งเหตุผลและไม่เพิ่มบางส่วน |
| TEA-02 | คู่เดิม → “มอบคู่ให้ตนเอง” → “ประเมินกลุ่ม” เลือกและยืนยันส่ง | Owner มีคู่นั้นในแบบประเมิน ส่ง revision ได้ ใช้น้ำหนักผู้สอนตามที่ตั้งไว้ |
| TEA-03 | กดมอบคู่เดิมให้ตนเองซ้ำ จากนั้นลองจำนวนเพิ่มมากกว่าผู้มีสิทธิ์เหลือ | ปฏิเสธพร้อมเหตุผล จำนวนของคู่ไม่เพิ่มซ้ำจากรายการที่ปฏิเสธ |
| TEA-04 | Co เข้าเมนูเดียวกัน มอบ Group ให้ตนเองและส่งจริง เปิดรายงาน จากนั้นสลับ TA | Co ประเมินและอ่านรายงานได้; TA ไม่มีสิทธิ์สร้างงาน/ประเมินในฐานะอาจารย์/อ่านรายงานคะแนน; Co ไม่มีสิทธิ์ Final/Reopen |

หากเพิ่มนักศึกษาแล้วผู้ได้รับคู่ไม่ใช่ Student 1/2 ให้ตรวจจำนวน/ข้อความสำเร็จและ audit ผ่าน UI ระบุว่าการเปิดลิงก์แจ้งเตือนของบัญชีนั้น BLOCKED จนมีบัญชีตัวเลือกที่เข้าถึงได้ ไม่เดาว่าแจ้งเตือนถูกอ่านแล้ว

### 10.1 ตารางคำนวณอิสระก่อนตัดสินผลตัวเลข

ใช้ค่าจริงจากไฟล์ CSV ของ snapshot เดียวกันและเครื่องคิดเลข อ่านน้ำหนัก/คะแนนเต็มของงานนั้นจากหน้าจัดการงานหรือ Metadata ของ Excel

- แต่ละเกณฑ์: `คะแนนถ่วง = คะแนนเต็มของด้าน × (น้ำหนัก % ÷ 100) × (floor + (ceiling − floor) × q)`
- รวมคะแนนถ่วงของด้านนั้นเป็น Group score หรือ Individual score เมื่อมีข้อมูลเพียงพอ กรณี Override ให้ใช้ค่าที่ปรับแทนองค์ประกอบนั้น
- `p = จำนวนส่ง ÷ จำนวนมอบหมาย`; ค่าเริ่มต้น `M = 1` เมื่อ `p ≥ 0.90` มิฉะนั้น `M = p ÷ 0.90` กรณีไม่มีคู่มอบหมายให้บันทึกสถานะที่ระบบให้ ไม่หารด้วยศูนย์
- `Total = (Group score + Individual score) × M` นักศึกษาที่ข้อมูลไม่ถึง anonymity threshold อาจยังไม่เห็น Individual/Total แม้ผู้สอนเห็นตัวเลข
- ตัวอย่างฝึกคิดเท่านั้น: คะแนนเต็ม Group 15, เกณฑ์เดียว 100%, q = 0.5, floor/ceiling = 0.6/1 → Group = 12; Individual เต็ม 5 เงื่อนไขเดียวกัน → 4; ถ้า M = 1 รวม = 16 ตัวเลขนี้ไม่ใช่ค่าที่บังคับให้ทุก fixture ได้

| รายการที่ต้องกรอกก่อนให้ผล EXP-03 | Student 1 | Student 2 |
|---|---|---|
| Snapshot / ด้าน / เกณฑ์ / q / น้ำหนัก | | |
| Group score ที่คำนวณ | | |
| Individual score ที่คำนวณ หรือเหตุผลข้อมูลไม่พอ | | |
| Answered / Assigned / p / M | | |
| Total ที่คำนวณ / Total ใน CSV / Total หน้าเว็บ | | |
| ต่างกันเท่าไร / มี Override หรือไม่ | | |

CSV ปัดองค์ประกอบ/q เป็น 4 ตำแหน่ง ส่วนหน้าเว็บปัด 2–3 ตำแหน่ง สำหรับการตรวจด้วยมือเทียบคะแนนรวมที่ 2 ตำแหน่งโดยยอมให้ต่างไม่เกิน 0.02 จากการปัดของข้อมูลตั้งต้นเท่านั้น ถ้าต่างมากกว่านั้นหรือมีความต่างที่อธิบายไม่ได้ให้ FAIL และเก็บไฟล์ snapshot เดิมไว้ตรวจ ห้ามใช้เลข 16.94 จากเครื่องผู้พัฒนาเป็นคำตอบตายตัว

## 20. สรุปผลและส่งกลับ

1. เติม [แบบบันทึกผล](testing/MANUAL_UI_RESULTS_TEMPLATE.md) แยกทุก ID ใส่เหตุผลของ BLOCKED/NOT RUN รวมถึง fixture ที่ไม่มี
2. กรณี FAIL ใช้รหัส `BUG-01`, `BUG-02` พร้อมบทบาท ห้อง/งาน/หน้าจอ ขั้นตอน ค่าที่กรอก สิ่งที่คาด สิ่งที่เกิดจริง และภาพที่เห็นข้อความผิดพลาด
3. เก็บไฟล์รายงาน/CSV/XLSX ของ snapshot ที่ผิดไว้ในเครื่อง ระบุชื่อไฟล์และเลข snapshot ใน bug report ไม่แนบฐาน/backup/token/session หรือ `.verification` ทั้งชุด
4. จดสถานะหลังทดสอบ เช่น ห้องไหนถูก archive, ใครถูกถอด, งานไหน Final เพื่อให้ผู้ตรวจซ้ำเข้าใจสภาพเริ่มต้นรอบถัดไป งานถอนควรใช้ห้องแยกตามคู่มือและไม่ลองเพิ่มนักศึกษาที่ถูกถอนกลับด้วย staff form
5. ส่งผลให้เจ้าของโครงงานผ่านช่องทางที่ตกลงกัน ยังไม่เผยแพร่รายงานหรือส่งข้อความให้ผู้อื่นอัตโนมัติ

**เกณฑ์พร้อมสาธิต:** เส้นทาง Owner → Student Group/Individual → คะแนน/รายงาน → Final/อุทธรณ์ และทีมผู้สอนทำได้ตามกรณีที่เลือก ไม่มี FAIL ที่ทำให้สิทธิ์รั่ว ข้อมูลหาย หรือคะแนนผิดอธิบายไม่ได้; ทุกข้อที่ข้ามระบุไว้ชัด การผ่านรอบสั้นไม่เท่ากับผ่านครบคู่มือนี้หรือ PRD ทุกข้อ
