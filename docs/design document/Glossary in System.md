# Glossary in System — ศัพท์ที่ใช้ใน PairEval

เอกสารนี้นิยามคำที่ใช้ใน [PRD v2.1](pairwise_evaluation_prd%201.md), [ภาพรวมระบบ](00_Overview_ภาพรวมระบบ.md) และหน้าจอเดโม เมื่อความหมายหรือสูตรต่างกันจะระบุ **ระบบเต็ม v2.1** กับ **Demo** แยกกัน หัวข้อ 6–7 เป็นคำของระบบเต็มที่ยังไม่ใช่ฟีเจอร์เดโม

## 1. ผู้ใช้และโครงสร้างชั้นเรียน

| คำอังกฤษ                         | คำไทย / ความหมายในระบบ                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------ |
| **PairEval**                     | ชื่อระบบประเมินผลงานด้วยการเปรียบเทียบเป็นคู่                                              |
| **Demo**                         | รุ่นสาธิตที่ใช้ข้อมูลสังเคราะห์และบัญชีตัวอย่าง                                            |
| **Instructor**                   | ผู้สอนที่จัดการห้อง งาน คู่ประเมิน รายงาน และไฟล์ส่งออก                                    |
| **Student**                      | นักศึกษาที่ประเมินคู่ที่ตนได้รับและดูคะแนนเฉพาะตน                                          |
| **Evaluator**                    | ผู้ที่ได้รับมอบหมายให้ตอบผลเปรียบเทียบคู่หนึ่ง ๆ; Demo เป็นนักศึกษา ส่วน v2.1 รวมผู้สอนที่ประเมินด้วย |
| **Classroom**                    | ห้องเรียนที่รวมนักศึกษา กลุ่ม และงานประเมิน                                                |
| **Group**                        | กลุ่มนักศึกษาภายในห้องเรียน ใช้เป็นรายการที่ถูกเปรียบเทียบใน Group Evaluation              |
| **Membership**                   | ความสัมพันธ์ที่บอกว่านักศึกษาคนใดอยู่ห้องและกลุ่มใด                                        |
| **Roster**                       | รายชื่อนักศึกษาที่นำเข้าห้องเรียน; Demo ใช้ CSV `email,groupname` ส่วนระบบเต็ม v2.1 ใช้ `email,group_name` และคอลัมน์เสริม `student_id,display_name` |
| **CSV (Comma-Separated Values)** | ไฟล์ข้อความที่ใช้เครื่องหมายจุลภาคคั่นคอลัมน์ เดโมใช้สำหรับนำเข้ารายชื่อและส่งออกสรุปคะแนน |
| **Synthetic data**               | ข้อมูลสมมติที่สร้างเพื่อทดสอบ/สาธิต ไม่ใช่รายชื่อหรือคะแนนจริง                             |

## 2. งาน เกณฑ์ และการจัดคู่

| คำอังกฤษ | คำไทย / ความหมายในระบบ |
|---|---|
| **Assignment** | งานประเมินในห้องเรียน กำหนดชื่อ คะแนนสูงสุด เกณฑ์ และกำหนดส่ง |
| **Group Evaluation** | การเปรียบเทียบผลงานกลุ่ม A กับกลุ่ม B โดยผู้ประเมินต้องไม่อยู่ในสองกลุ่มนั้น |
| **Individual Evaluation** | การเปรียบเทียบนักศึกษา A กับ B ภายในกลุ่มเดียวกัน โดยผู้ประเมินเป็นเพื่อนร่วมกลุ่มที่ไม่ใช่ A หรือ B |
| **Criterion / Criteria** | เกณฑ์ / หลายเกณฑ์ที่ใช้เปรียบเทียบ เช่น ความครบถ้วน; แต่ละเกณฑ์มีน้ำหนักคะแนน |
| **Weight / Weight percent** | น้ำหนักร้อยละของเกณฑ์; น้ำหนัก Group และ Individual ต้องรวม 100% แยกกัน |
| **Pair / Combination** | สองรายการ A–B ที่จะเปรียบเทียบกันตามเกณฑ์หนึ่ง โดยยังไม่ระบุผู้ประเมิน |
| **Pair Assignment** | รายการมอบหมายคู่ A–B ตามเกณฑ์ให้ evaluator คนหนึ่งตอบ; คู่เดียวกันมีหลายรายการมอบหมายเพื่อให้ได้ coverage |
| **Pairing Engine** | ส่วนที่สร้างคู่ ตรวจผู้ประเมินที่มีสิทธิ์ และกระจายรายการมอบหมาย |
| **Eligible evaluator** | ผู้ประเมินที่ผ่านเงื่อนไขของคู่: Group ต้องอยู่นอกทั้งสองกลุ่ม; Individual ต้องอยู่กลุ่มเดียวกันแต่ไม่ใช่คนในคู่ |
| **Coverage target** | จำนวนผู้ประเมินต่างคนกันที่ต้องการต่อคู่ต่อเกณฑ์; Demo ตั้งไว้ 5 และปฏิเสธถ้าไม่ครบ ส่วน v2.1 อาจลดเป็น R_actual หลังตรวจ feasibility |
| **Coverage (pair assignment)** | จำนวนรายการมอบหมายที่สร้างให้คู่หนึ่งต่อเกณฑ์; ยังไม่ยืนยันว่ามีคนตอบแล้ว |
| **Answered coverage** | จำนวนคำตอบของคู่ที่อยู่ใน submission ล่าสุดที่ส่งแล้ว อาจน้อยกว่า coverage ที่มอบหมาย |
| **Preview / Planned** | ผลจำลองก่อนบันทึก แสดงคู่ จำนวนผู้มีสิทธิ์ และจำนวนรายการที่จะสร้าง |
| **Actual / Generated** | จำนวนรายการมอบหมายคู่ที่บันทึกจริงแล้วในฐานข้อมูล |
| **Workload** | จำนวนคู่ที่ evaluator ได้รับมอบหมาย; เดโมพยายามกระจายภาระ แต่ไม่รับประกันคนละ 5 คู่ |
| **Infeasible** | จัดคู่ให้ครบ target ตามข้อห้ามประเมินตนเองไม่ได้; เดโมแสดงเหตุผลและไม่บันทึกคู่ของงานนั้น |

## 3. การตอบและสถานะ

| คำอังกฤษ | คำไทย / ความหมายในระบบ |
|---|---|
| **Evaluation / Response** | การเลือกผลเปรียบเทียบ A–B ในแต่ละ Pair Assignment |
| **Choice** | ตัวเลือกคำตอบ 1–6 จากเอนเอียงไปทาง A มากที่สุดถึง B มากที่สุด; เดโมไม่มีค่ากลาง “เท่ากัน” |
| **Save draft / Draft** | บันทึกคำตอบร่างไว้ก่อน ยังไม่ถือว่าส่งและไม่นับคะแนน |
| **Submit / Submission** | ส่งชุดคำตอบที่มีอย่างน้อยหนึ่งคู่ เพื่อให้เป็นข้อมูลที่ใช้คำนวณคะแนน |
| **Re-submit** | ส่งคำตอบใหม่ก่อน deadline โดยสร้าง revision ใหม่ ไม่แก้ revision เก่า |
| **Submission revision** | รุ่นของคำตอบที่ส่งในแต่ละครั้ง แยก Group กับ Individual; คิดคะแนนจากรุ่นที่ส่งล่าสุดของแต่ละชนิด |
| **Latest submitted revision** | revision ที่ส่งล่าสุดของ evaluator สำหรับ Assignment และชนิดการประเมินหนึ่ง ๆ; draft หรือ revision เก่าไม่นับ |
| **Deadline** | วันและเวลาปิดรับของ Group หรือ Individual; หลังเวลานี้ดูได้แต่ Save/Submit ไม่ได้ |
| **Progress** | จำนวนคู่ที่ตอบแล้วเทียบกับจำนวนคู่ที่ได้รับมอบหมายในหน้าประเมิน |

## 4. คะแนนและรายงาน

| คำอังกฤษ | คำไทย / ความหมายในระบบ |
|---|---|
| **Pairwise comparison** | วิธีประเมินโดยเลือกว่ารายการ A หรือ B ดีกว่ากันตามเกณฑ์ แทนการให้คะแนนรายการเดี่ยวโดยตรง |
| **Point** | แต้มของ A และ B ที่แปลงจาก Choice 1–6; สองฝ่ายรวมกันได้ 1 ต่อคำตอบ |
| **Average point** | ค่าเฉลี่ยแต้มที่รายการหนึ่งได้รับจากคำตอบที่ส่งแล้วในเกณฑ์นั้น |
| **Normalization / Normalize** | สูตรของ **Demo**: ปรับค่าเฉลี่ยของรายการให้เป็นสัดส่วนรวม 1 ภายในเกณฑ์เดียวกัน; Group คิดทั้งห้อง และ Individual คิดภายในกลุ่ม **PRD v2.1 ไม่ใช้สูตรนี้** แต่ใช้ band mapping |
| **Base score** | คะแนนตั้งต้นจากผลประเมินและน้ำหนักเกณฑ์ ก่อนปรับตามสัดส่วนการส่งของนักศึกษา |
| **Completion ratio** | answered pairs / assigned pairs ของนักศึกษาหนึ่งคน แยก Group และ Individual เพื่อปรับคะแนนส่วนของผู้ส่งเมื่อส่งไม่ครบ |
| **Partial credit** | คะแนนบางส่วนเมื่อ Submit โดยตอบไม่ครบ คำนวณด้วย base score × completion ratio; ไม่หักคะแนนของคนอื่น |
| **Group score / Individual score / Total** | คะแนนส่วนกลุ่ม / ส่วนบุคคล / ผลรวมสองส่วนของนักศึกษา |
| **NO_DATA** | ยังมีข้อมูลคำตอบไม่พอให้คำนวณคะแนนของรายการหรือเกณฑ์นั้น จึงไม่แสดงตัวเลขที่แต่งขึ้น |
| **Interim / Final** | **Demo:** Final หลังครบ deadline ทั้งสองส่วนและมีข้อมูลพอคำนวณทุก item; มิฉะนั้น Interim **v2.1:** Final เมื่อ Owner กด Finalize และเก็บ snapshot แล้ว |
| **Report** | หน้าผู้สอนที่แสดงคะแนนและจำนวนคำตอบต่อคู่ตามเกณฑ์ |
| **My Score** | หน้านักศึกษาที่แสดงเฉพาะคะแนนของตน |
| **Export** | การดาวน์โหลดผลคะแนน; เดโมมี CSV summary แบบเดียว |

## 5. ส่วนประกอบทางเทคนิคและการเข้าถึง

| คำอังกฤษ | คำไทย / ความหมายในระบบ |
|---|---|
| **UI (User Interface)** | หน้าจอเว็บที่ผู้สอนและนักศึกษาใช้งาน |
| **API (Application Programming Interface)** | ช่องทางที่หน้าเว็บเรียกฝั่งเซิร์ฟเวอร์เพื่ออ่านหรือบันทึกข้อมูล |
| **API route** | ที่อยู่คำสั่งฝั่งเซิร์ฟเวอร์ของ Next.js สำหรับงาน เช่น สร้างห้องหรืออ่านคะแนน |
| **System Context Diagram** | ภาพขอบเขตที่แสดงผู้ใช้ สิ่งภายนอก และข้อมูลที่เข้า/ออกจาก PairEval |
| **System Architecture Diagram** | ภาพส่วนประกอบของแอปและทางที่ข้อมูลไหลระหว่างหน้าจอ เซิร์ฟเวอร์ และฐานข้อมูล |
| **Conceptual Data Diagram** | ภาพความสัมพันธ์ของข้อมูลหลักระดับแนวคิด ไม่ใช่รายละเอียดคอลัมน์ทุกตัวในฐานข้อมูล |
| **Next.js / TypeScript** | เครื่องมือสร้างเว็บแอป / ภาษาที่ใช้เขียนโค้ดของเดโม |
| **Scoring Engine** | ส่วนคำนวณคะแนนจากคำตอบใน revision ล่าสุด เกณฑ์ และน้ำหนัก |
| **Evaluation Store** | ส่วนอ่าน/บันทึก draft และ submission พร้อมตรวจสิทธิ์และ deadline |
| **Validation** | การตรวจว่าข้อมูลที่รับเข้าตรงรูปแบบและกติกาก่อนบันทึก เช่น CSV หรือน้ำหนักเกณฑ์ |
| **Transaction** | การบันทึกหลายรายการเป็นชุดเดียว; หากเกิดข้อผิดพลาดจะไม่เหลือข้อมูลเพียงบางส่วน |
| **Session** | สถานะบัญชีตัวอย่างที่เลือกในเดโม ใช้ตรวจบทบาทและเจ้าของข้อมูลที่เซิร์ฟเวอร์; ไม่ใช่การยืนยันตัวตนสำหรับข้อมูลจริง |
| **Role** | ประเภทผู้ใช้ที่กำหนดสิทธิ์; Demo มี Instructor/Student ส่วน v2.1 แยก Owner, Co-teacher, TA, Student และ SYSTEM_ADMIN |
| **SQLite** | ฐานข้อมูลแบบไฟล์ที่เดโมใช้เก็บห้อง งาน คู่ draft และ submission |
| **Seed / Reset** | การสร้างข้อมูลสังเคราะห์เริ่มต้น / ล้างแล้วสร้างฐานข้อมูลเดโมใหม่ |

## 6. คำในข้อกำหนดระบบเต็มที่ยังไม่ใช่ความสามารถเดโม

| คำอังกฤษ | ความหมายและสถานะ |
|---|---|
| **Google OAuth / OIDC** | การเข้าสู่ระบบด้วยบัญชี Google และตรวจ ID token ตาม PRD v2.1; เดโมยังใช้การเลือกบัญชีสังเคราะห์ |
| **Instructor evaluation weight** | น้ำหนักคะแนนของคำตอบผู้สอนเทียบกับนักศึกษา; เดโมยังไม่มีการประเมินโดยผู้สอน |
| **Group re-assignment / Re-generate pairs** | ย้ายสมาชิกกลุ่มและสร้างคู่รุ่นใหม่; DQ-09 เลือกเก็บคู่/คำตอบรุ่นเก่าเพื่อ audit และไม่ปนกับรุ่นปัจจุบัน เดโมยังไม่รองรับ |
| **Raw comparison export** | ไฟล์ผลเปรียบเทียบรายคู่; v2.1 ให้ใช้รหัสผู้ประเมินแบบ pseudonym เป็นค่าเริ่มต้น เดโมยังไม่มี |
| **Anonymized / Pseudonymous export** | ไฟล์ที่ไม่เผยตัวตนผู้ประเมินตรง ๆ; v2.1 เปิดเผยตัวตนจริงได้เฉพาะ Owner ที่ยืนยันเจตนาและมี audit |
| **Excel export (.xlsx)** | การส่งออกไฟล์สมุดงาน Excel; เดโมส่งออกเฉพาะ CSV ซึ่งสามารถนำเข้า Excel ได้ |
| **Notification** | การแจ้งเตือนผู้ใช้ เช่น เมื่อคู่เปลี่ยน; เดโมยังไม่มีบริการแจ้งเตือน |

## 7. ศัพท์เฉพาะของ PRD v2.1

| คำอังกฤษ                                         | ความหมายในระบบเต็ม                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **Quality index (q)**                          | ค่าเฉลี่ยแต้ม pairwise แบบถ่วงน้ำหนักผู้ประเมินของ item/criterion อยู่ในช่วง 0–1            |
| **Evaluator weight (w_e)**                     | น้ำหนักของคำตอบผู้ประเมินในค่าเฉลี่ยของ q; นักศึกษา = 1.0 และผู้สอน = instructor_weight |
| **Coverage (R) / Workload (k)**              | จำนวนผลที่ต้องการต่อคู่ / จำนวนคู่ที่มอบหมายต่อผู้ประเมินหนึ่งคนในเกณฑ์นั้น                 |
| **Band mapping / Score floor / Score ceiling**   | แปลง q เป็นสัดส่วนคะแนนด้วย floor + (ceiling−floor)×q; ค่าเริ่มต้น 0.60–1.00 ตาม PRD    |
| **Instructor weight**                            | น้ำหนักของคำตอบผู้สอนใน weighted mean; เป็น float ต่อ Assignment ไม่ใช่จำนวน vote ที่ทำซ้ำ  |
| **Participation ratio (p) / Multiplier (M)** | สัดส่วนงานประเมินที่ส่ง / ตัวคูณตาม threshold เพื่อปรับคะแนนส่วนตัวของผู้ประเมิน            |
| **LOW_CONFIDENCE**                               | ธงเมื่อข้อมูลเปรียบเทียบ item ต่ำกว่าเกณฑ์ ไม่ควร Finalize อัตโนมัติ                        |
| **k-anonymity (k_min)**                          | เกณฑ์ผู้ประเมินที่ส่งแล้วขั้นต่ำก่อนแสดงคะแนน Individual แก่นักศึกษา                        |
| **Publish / Unpublish / Finalize**               | เปิดงานและสร้างคู่ / กลับไปแก้ก่อนเปิดใหม่ / ล็อกคะแนนพร้อม snapshot ตาม lifecycle ของ v2.1 |
| **Interim score / Final score**                  | คะแนนระหว่างทางที่อาจเปลี่ยนได้ / คะแนนหลัง Owner Finalize และล็อก snapshot ใน v2.1         |
| **Score snapshot**                               | สำเนา input/output และสูตรของการคำนวณ ณ การ Finalize เพื่อให้ตรวจย้อนหลังได้                |
| **Audit event**                                  | บันทึก actor/action/resource/เวลาและเหตุผลแบบ append-only สำหรับการกระทำสำคัญ               |
| **Owner / Co-teacher / TA / SYSTEM_ADMIN**       | บทบาทในห้องและระดับระบบที่มีสิทธิ์ต่างกันตาม PRD หัวข้อ 3; Demo ยังไม่มีครบ                       |
| **OIDC / sub**                                 | มาตรฐานยืนยันตัวตนกับ Google และรหัสตัวตนถาวรหลังเชื่อม roster ครั้งแรก                     |

## 8. การจัดคู่ ข้อมูล และการเปลี่ยนสถานะใน PRD v2.1

| คำอังกฤษ                                                   | ความหมายในระบบ                                                                                            |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Item / Side**                                            | สิ่งที่ถูกประเมิน (Group หรือ Student) / ฝั่ง GROUP หรือ INDIVIDUAL ของงาน                                |
| **Comparison**                                             | ผลเลือก 1 ครั้งของ evaluator ต่อ pair และ criterion; ต่างจาก **Pair Assignment** ที่เป็นงานมอบหมายก่อนตอบ |
| **Eligibility graph**                                      | กราฟเชื่อมคู่กับผู้ประเมินที่ผ่านเงื่อนไข ใช้ตรวจว่าแจกงานได้จริง                                         |
| **Feasibility**                                            | ความเป็นไปได้ที่จะสร้างคู่ครบภายใต้ coverage, สิทธิ์ผู้ประเมิน และ workload cap                           |
| **Deterministic constrained matching / Min-cost max-flow** | วิธีจัดสรรภายใต้ข้อจำกัดที่ได้ผลซ้ำเมื่อ input และ seed เหมือนเดิม                                        |
| **Canonical pair**                                         | คู่ที่เก็บ ID ตามลำดับคงที่เพื่อกัน A–B กับ B–A ซ้ำกัน                                                    |
| **Seed / Generation**                                      | ค่าเริ่มการสุ่มที่ทำซ้ำได้ / รุ่นของคู่ที่สร้างใหม่หลังเปลี่ยนข้อมูล                                      |
| **Workload vector / k_max**                              | จำนวนคู่ต่อผู้ประเมินแต่ละคน / เพดานจำนวนคู่สูงสุดต่อคน                                                   |
| **R_actual / Coverage**                                  | เป้าความครอบคลุมที่ทำได้จริงหลังตรวจ feasibility / จำนวนงานหรือคำตอบต่อคู่ตามบริบท                        |
| **Artifact**                                               | ลิงก์ผลงานของแต่ละ Group หรือ Student ที่ต้องแสดงให้ผู้ประเมินเห็นขณะเปรียบเทียบ                          |
| **Upsert / Atomic import**                                 | นำเข้าซ้ำเพื่อเพิ่มหรือแก้ข้อมูล / นำเข้าแบบสำเร็จทั้งไฟล์หรือไม่บันทึกเลย                                |
| **Immutable revision / Snapshot**                          | รุ่นคำตอบหรือคะแนนที่บันทึกแล้วไม่แก้ทับ เพื่อให้ตรวจย้อนหลังได้                                          |
| **Reopen / Override / Archive**                            | เปิดผลที่ Finalized กลับมาพิจารณา / ปรับคะแนนพร้อมเหตุผล / เก็บงานหรือห้องโดยไม่ใช้งานปกติ                |

## 9. ความปลอดภัย ความเป็นส่วนตัว และคุณภาพ

| คำอังกฤษ | ความหมายในระบบ |
|---|---|
| **Authentication / Authorization** | พิสูจน์ว่าเป็นใคร / ตรวจว่าคนนั้นมีสิทธิ์ทำสิ่งใดกับข้อมูลนั้น |
| **Classroom scope / Ownership** | ขอบเขตข้อมูลของห้องเรียน / ความเป็นเจ้าของงานหรือคู่ที่ API ต้องตรวจทุกครั้ง |
| **FACULTY entitlement** | สิทธิ์ระดับระบบที่อนุญาตให้สร้าง Classroom โดยไม่ให้สิทธิ์อ่านคะแนนห้องอื่น |
| **Verified email / email_verified / Hosted domain** | อีเมลที่ผู้ให้บริการยืนยันแล้ว / claim ยืนยันอีเมล / โดเมนองค์กรที่ต้องตรวจจาก token |
| **Pseudonym / Pseudonymous ID** | รหัสแทนตัวตนผู้ประเมินที่ไม่เปิดเผยชื่อจริงโดยตรง; ยังเชื่อมกลับได้ภายใต้สิทธิ์ที่กำหนด |
| **Privacy notice / Data retention / Data subject access** | ข้อแจ้งการใช้ข้อมูล / ระยะเก็บข้อมูล / สิทธิ์ขอสำเนาข้อมูลของตน |
| **PDPA** | กฎหมายคุ้มครองข้อมูลส่วนบุคคลไทยที่ PRD ระบุเป็นข้อจำกัดของระบบเต็ม |
| **Quality Signal / EXCLUDED** | ธงบอกความผิดปกติเพื่อให้ผู้สอนตรวจ / คำตอบที่ผู้สอนตัดออกพร้อมเหตุผล ไม่ใช่การตัดอัตโนมัติ |
| **Straight-lining / Position bias / Intransitivity** | เลือกค่าเดิมซ้ำมากผิดปกติ / เอนเอียงเลือกฝั่งซ้ายหรือขวา / ผล A>B, B>C แต่ C>A |
| **Speed run / Self-group favoritism / Low rater agreement** | ตอบเร็วผิดปกติ / เอนเอียงให้เพื่อนกลุ่มตน / ผู้ประเมินเห็นต่างกันมากในเกณฑ์เดียว |
| **Audit log / Append-only** | บันทึกเหตุการณ์สำคัญ / เพิ่มรายการได้แต่แก้หรือลบรายการเดิมไม่ได้ |
| **Appeal / Notification** | คำร้องทบทวนคะแนน / การแจ้งเตือนเหตุการณ์ที่เกี่ยวกับงานโดยไม่ใส่คะแนนในเนื้อความ |
| **IDOR / Formula injection** | การเดา ID เพื่อเข้าข้อมูลที่ไม่มีสิทธิ์ / การใส่ข้อความใน CSV ให้โปรแกรมตารางคำนวณเป็นสูตร |

## 10. สัญญา API การทดสอบ และตัวชี้วัด

| คำอังกฤษ | ความหมายในระบบ |
|---|---|
| **REST / JSON / Endpoint** | รูปแบบ API / รูปแบบข้อมูล / ที่อยู่คำสั่งแต่ละรายการ |
| **Idempotent / Idempotency-Key** | เรียกคำสั่งซ้ำแล้วไม่เกิดผลเพิ่ม / คีย์ที่ช่วยกัน Submit ซ้ำ |
| **Rate limit / Retry-After** | เพดานจำนวนคำขอ / เวลาที่ API บอกให้รอก่อนลองอีกครั้ง |
| **Success schema / Error code / Pagination** | รูปแบบผลสำเร็จ / รหัสข้อผิดพลาดคงที่ / การแบ่งผลลัพธ์เป็นหน้า |
| **API contract / Contract test** | ข้อตกลง field, status, สิทธิ์ และตัวอย่างคำขอ/คำตอบของ API / การทดสอบว่าระบบจริงทำตามข้อตกลงนั้น |
| **Response envelope / `data` / `meta`** | รูปหุ้มคำตอบ JSON ที่แยกข้อมูลหลักใน `data` ออกจากข้อมูลประกอบ เช่น `requestId` ใน `meta` |
| **Cursor / `nextCursor`** | ตัวชี้ตำแหน่งแบบไม่เปิดเผยข้อมูลภายใน เพื่อขอผลลัพธ์หน้าถัดไปจากรายการที่แบ่งหน้า |
| **Field allowlist / Opaque ID** | รายการ field ที่อนุญาตให้รับหรือส่งสำหรับบทบาทหนึ่ง / รหัสที่ไม่ควรอ่านย้อนเพื่อเดาตัวตนหรือโครงสร้างฐานข้อมูล |
| **HTTP 200/201/204/400/401/403/404/409/422/429** | รหัสผลสำเร็จทั่วไป / สร้างใหม่ / สำเร็จไม่มีเนื้อหา / รูปแบบผิด / ยังไม่ยืนยันตัวตน / ไม่มีสิทธิ์ / ไม่พบหรือซ่อนทรัพยากร / สถานะขัดกัน / ผิดกฎธุรกิจ / เรียกเกินเพดาน |
| **UTC / ISO 8601** | เวลามาตรฐานสำหรับเก็บและส่ง timestamp / รูปแบบข้อความเวลา เช่น `2026-09-29T08:00:00Z` |
| **p95 / p99 / Concurrent users** | เวลาไม่เกินค่าที่กำหนดสำหรับ 95%/99% ของคำขอ / จำนวนผู้ใช้พร้อมกัน |
| **RPO / RTO** | ระยะข้อมูลที่ยอมสูญหายได้ / เวลาเป้าหมายสำหรับกู้บริการ |
| **Unit / Integration / E2E / Property-based / Golden / Load test** | ทดสอบหน่วยโค้ด / ส่วนที่เชื่อมกัน / เส้นทางใช้งานจริง / คุณสมบัติหลายชุดข้อมูล / ตัวอย่างผลที่กำหนดไว้ / ภาระระบบ |
| **WCAG / WAI-ARIA / Screen reader** | แนวทางการเข้าถึงเว็บ / รูปแบบควบคุมที่ช่วยเทคโนโลยีอำนวยความสะดวก / โปรแกรมอ่านหน้าจอ |
| **PRD / Requirement / Traceability / Verification evidence** | เอกสารความต้องการผลิตภัณฑ์ / ข้อกำหนด / การตามรอยข้อกำหนดไปถึงแบบและผลทดสอบ / หลักฐานว่าตรวจผ่าน |
| **Source of truth / Acceptance criteria / Design draft / Implementation** | เอกสารต้นทางที่มีอำนาจเมื่อข้อความต่างกัน / เงื่อนไขตรวจว่าข้อกำหนดผ่าน / แบบร่างที่ยังรอทบทวน / ระบบที่พัฒนาใช้งานจริง |
| **MUST / SHOULD / MAY** | ระดับบังคับ / ควรทำพร้อมเหตุผลถ้าไม่ทำ / ทางเลือก ตามคำที่ PRD ใช้ |
| **Milestone / M1–M4 / Success metric** | จุดส่งมอบตามแผน / ระยะพัฒนาทั้งสี่ / ตัวชี้วัดผลหลังใช้งาน |
| **Decision record / OQ / DQ** | บันทึกคำตัดสินพร้อมเหตุผล / คำถามเปิดใน PRD / ช่องว่างที่พบในเอกสารออกแบบ |

## 11. ชื่อปัญหา สถานะ และชื่อข้อมูลที่ปรากฏในไฟล์ออกแบบ

| คำอังกฤษ                                                                          | ความหมายในบริบท PairEval                                                                          |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Absolute scoring bias**                                                         | อคติจากการให้คะแนนชิ้นงานแบบเดี่ยวที่มาตรฐานอาจเปลี่ยนตามลำดับการตรวจ                             |
| **Free-rider**                                                                    | สมาชิกที่มีส่วนร่วมต่ำแต่ได้คะแนนกลุ่มเท่าคนที่ทำงานมาก                                           |
| **Peer rating inflation**                                                         | การให้คะแนนเพื่อนสูงคล้ายกันหมดจนแยกผลงานไม่ออก                                                   |
| **Success metrics**                                                               | ตัวชี้วัดผลหลังใช้จริง เช่น participation, เวลาใช้งาน, การกระจายคะแนน และอัตรา appeal             |
| **M1 Walking Skeleton / M2 Core Complete / M3 Trustworthy / M4 Production Ready** | ลำดับส่งมอบระบบเต็ม 4 ระยะ; ต่างจาก M1–M6 ใน หัวข้อ 1.4 ซึ่งเป็นตัวชี้วัดความสำเร็จ                     |
| **PENDING / WITHDRAWN**                                                       | สถานะบัญชีที่ยังไม่เข้าใช้ / สถานะสมาชิกที่ถอนรายวิชาตามข้อสรุป OQ-4 สำหรับพัฒนา; schema PRD v2.1 ยังต้องเพิ่ม field นี้ |
| **PAIR_ASSIGNMENT / pair_assignment**                                         | ตาราง/แนวคิดคู่ที่มอบหมายให้ผู้ประเมินก่อนมีคำตอบ                                                 |
| **evaluation_drafts, submission_revisions, submission_answers**             | ตารางของ Demo สำหรับคำตอบร่าง, รุ่นที่ส่ง และคำตอบในรุ่นนั้น                                      |
| **comparison_revision, submission**                                           | ตารางระบบเต็มสำหรับ snapshot คำตอบ ณ การ Submit และเหตุการณ์ส่งแต่ละครั้ง                         |
| **computed_score, score_snapshot, score_override**                          | คะแนน Interim ปัจจุบัน / สำเนาผลคำนวณถาวร / การปรับคะแนนพร้อมเหตุผล                               |
| **classroom_member, group_artifact, individual_artifact**                   | สมาชิก/บทบาทในห้อง และลิงก์ผลงานต่อกลุ่มหรือนักศึกษา                                              |
| **audit_event**                                                                 | รายการเหตุการณ์สำคัญใน audit storage แยกจากฐานข้อมูลใช้งาน                                        |
| **google_sub / display_left**                                                 | รหัสตัวตนจาก OIDC / ฝั่งซ้ายที่แสดงจริงของ comparison ซึ่งต้องเก็บเพื่อแปล choice ถูกต้อง         |
| **instructor_weight / min_comparisons**                                       | น้ำหนักคำตอบผู้สอน / จำนวน comparison ขั้นต่ำก่อนผลไม่ติด LOW_CONFIDENCE                          |
| **opens_at**                                                                    | เวลาเริ่มเปิด Assignment ที่ PRD v2.1 ไม่ได้กำหนด; DQ-13 เลือกเปิดทันทีหลัง Publish จึงยังไม่เพิ่ม field นี้ |
| **aria-live**                                                                   | คุณสมบัติ HTML/ARIA ที่ให้ screen reader แจ้งสถานะ Autosave เมื่อเปลี่ยน                          |
| **LMS / LTI 1.3**                                                                 | ระบบจัดการเรียนรู้ของมหาวิทยาลัย / มาตรฐานเชื่อมเครื่องมือภายนอกกับ LMS; OQ-5 เลือก Export สำหรับ v1.0 และไม่เชื่อม LMS |
| **URL / README**                                                                  | ที่อยู่ลิงก์ไปผลงานหรือหน้าเว็บ / เอกสารวิธีเปิดและใช้ PairEval-Demo                              |
| **HTTPS / HSTS**                                                                  | การสื่อสารเว็บแบบเข้ารหัส / นโยบายบังคับให้เบราว์เซอร์ใช้ HTTPS                                   |
| **UX / SD / AA**                                                                  | ประสบการณ์ผู้ใช้ / ส่วนเบี่ยงเบนมาตรฐานใน success metric / ระดับเป้าหมายการเข้าถึงของ WCAG 2.2    |
| **UNANSWERED / REOPENED / ARCHIVED**                                        | สถานะยังไม่ตอบ / เปิดผลกลับมาพิจารณา / เก็บออกจากการใช้งานปกติในแผนภาพสถานะ                       |
| **DB / Authorization (AZ ในแผนภาพ)**                                              | ฐานข้อมูล / ชั้นตรวจสิทธิ์ที่คั่นระหว่าง API กับข้อมูลและบริการ                                   |
| **Generation / Soft-invalidate** | รุ่นของคู่ที่สร้างเมื่อ Publish / ปิดรุ่นเดิมจากการใช้งานปัจจุบันโดยยังเก็บประวัติคู่และคำตอบเพื่อ audit |
| **Erratum / Errata Proposal** | ข้อเสนอแก้ข้อความ PRD ที่ขัดกับข้อสรุปออกแบบ; ยังไม่เปลี่ยนต้นฉบับจนกว่าจะออกเวอร์ชันใหม่ |

## 12. ชื่อ field และตัวชี้วัดที่ใช้ใน PRD ต้นฉบับ

| คำอังกฤษ | ความหมายในบริบท PRD |
|---|---|
| **Document ID / Version / Supersedes / Last updated** | รหัสเอกสาร / รุ่น / รุ่นที่ถูกแทน / วันที่ปรับปรุงล่าสุด |
| **Document owner / Required reviewers** | ผู้รับผิดชอบเอกสาร / ผู้ที่ต้องร่วมทบทวนก่อนอนุมัติ |
| **Role permission matrix / Teaching Assistant** | ตารางสิทธิ์แต่ละบทบาท / ผู้ช่วยสอน (TA) |
| **Participation rate / Median time-on-task** | สัดส่วนผู้ส่งครบ / เวลาใช้งานมัธยฐานต่องาน |
| **Score dispersion / Instructor override rate / Dispute rate / Low-confidence items** | การกระจายคะแนน / อัตราปรับคะแนนโดยผู้สอน / อัตราอุทธรณ์ / สัดส่วนรายการที่ข้อมูลประเมินไม่พอ |
| **Free-rider problem / Low coverage** | ปัญหาสมาชิกไม่ร่วมทำงานแต่ได้คะแนนกลุ่ม / คู่หรือ item มีผลประเมินน้อย |
| **group_name, student_id, display_name** | ชื่อกลุ่ม, รหัสนักศึกษา และชื่อที่แสดงใน roster/ฐานข้อมูล |
| **group_max_score, individual_max_score** | คะแนนสูงสุดของส่วนกลุ่มและส่วนบุคคลใน Assignment |
| **artifact_url / score_snapshot_item** | ลิงก์ผลงานของ item / รายการคะแนนย่อยใน snapshot ที่ล็อกแล้ว |
| **s_left, s_right, extra, k_e** | แต้มฝั่งซ้าย/ขวา, จำนวนคนที่ได้ workload เพิ่มหนึ่งคู่, workload ของ evaluator คนที่ e |
| **group_component, final_personal_score** | คะแนนตั้งต้นส่วนกลุ่ม / คะแนนส่วนตัวหลังใช้ participation multiplier |
| **numeric** | ชนิดตัวเลขฐานข้อมูลที่รักษาทศนิยมแน่นอนกว่าการใช้ float สำหรับคะแนน |
| **requestId / message** | รหัสติดตามคำขอ API / ข้อความอธิบายข้อผิดพลาดที่มนุษย์อ่านได้ |
| **Pseudonymous evaluator ID / k-anonymity threshold** | รหัสแทนผู้ประเมิน / จำนวนผู้ส่งขั้นต่ำก่อนเปิดคะแนน Individual |
| **Property-based test** | การทดสอบกฎที่ต้องจริงเสมอกับข้อมูลหลายรูปแบบ เช่น ขนาดกลุ่ม/coverage ต่างกัน |
| **Participation multiplier** | ตัวคูณ M ที่ปรับคะแนนส่วนตัวตามสัดส่วนงานประเมินที่ส่ง |
| **Elo / TrueSkill / z-score / percentile rank** | วิธีจัดอันดับหรือแปลงคะแนนที่ PRD หัวข้อ 9.6 พิจารณาแต่ยังไม่เลือกใช้ในรุ่นแรก |

## ขอบเขตการตรวจศัพท์
